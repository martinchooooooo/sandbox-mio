# Herdr Multiplexer E2E Test Plan

Test plan for the zellij-to-Herdr swap built in [02_dev.md](02_dev.md). The spike in [spike/README.md](spike/README.md) ran on 2026-11-18 against Podman through a standalone russh probe, not through the app; its attach, mouse, clipboard and persistence evidence is raw-byte only. Phases A, B and C are implemented and all four affected specs are written and green against the Podman test machine (see "Run results"): `embedded-workspace.spec.ts`, `base-image-recipe.spec.ts`, and the two new specs `herdr-multiplexer-missing.spec.ts` (old-image error) and `herdr-long-name.spec.ts` (hashed session name). Shared helpers (`expectedSessionName`, `liveHerdrSessions`, `waitForTerminalAttached`) live in `e2e/lib/herdr.ts`. Phase D's manual renderer checks are a separate matter, see "Manual checks".

## Goal

Prove through the real application that a sandbox's native terminal runs Herdr, not zellij. The real code path:

1. `open_terminal_pane` (`src-tauri/src/commands/terminal.rs`) calls `create_session()` in `src-tauri/src/terminal/mod.rs`, which runs the start script from `create_argv()` as a `podman exec` with `workdir` set to the workspace directory, inside the real sandbox container built from base image 8.
2. The same function then attaches `herdr --session <name>` from `client_command()` over the in-process russh SSH channel to the sandbox's `mio-sshd`.
3. The Herdr binary comes from the pinned, checksum-verified release asset in `src-tauri/resources/Containerfile`, built by `ensure_image` in `src-tauri/src/provider/mod.rs`.

A weaker test would fail to cover:

- The mock terminal host (`MockTerminalHost`, `src-tauri/src/terminal/mock.rs`) used by the light tier echoes bytes and never runs `create_argv()`, `session_name()` or any exit-code mapping, so no light spec proves a Herdr session exists.
- Reading `herdr session list --json` without opening the terminal through the UI would not show that the app starts the server; the spec must assert no session exists before the Terminal tab opens and exactly one after.
- Checking that the Containerfile text pins a version does not show the binary runs; the recipe spec is a static guard only and the base-image build specs plus the terminal attach carry the runtime proof.

## Chosen approach

Tier: `standard`, per `e2e/AGENTS.md` decision rule 1. Every item below needs a real container, a real `podman exec` and a real SSH attach, except the static recipe guard, which reads files and needs no machine but lives in `standard` beside the other base-image specs. Nothing downloads a large asset beyond the base-image build the tier already performs, and nothing chains a remote deploy, so `heavy` is not warranted. Serialisation cost: these run under the host lock like every `standard` run, and the `BASE_IMAGE_VERSION` bump to 8 means each worktree's first `standard` run rebuilds the base image and needs outbound access to github.com for the Herdr asset.

Host paths: the specs add none. Herdr's sockets and state live under `/root/.config/herdr` inside the sandbox; the host's own `~/.herdr` and `%APPDATA%\herdr` are never read or asserted on (a spec that ran `herdr` on the host would reach the developer's real session). Every `herdr` call goes through `podman exec` against `LOCAL_CONNECTION` (`mio-tests`). Workspace paths still derive from `e2e/lib/run-identity.ts`.

No `e2e/wdio.conf.ts` change and no new provisioning are needed.

### Why the old-image error is `standard`

The mapping from exit 127 to `TerminalError::MultiplexerMissing` happens in `create_session()` after a real `podman exec` of the start script. The mock terminal host never reaches it and `podman exec` is not a scriptable key for the SSH path, so a light spec cannot reach the code under test. In `standard`, a sandbox on base image 8 can be turned into an "old" one deterministically by moving `/usr/local/bin/herdr` aside inside the container (`podman exec <name> mv /usr/local/bin/herdr /usr/local/bin/herdr.off`); the start script's `command -v herdr` then fails and the exec exits 127, exactly as on a pre-bump sandbox. This avoids building an image-7 sandbox, which would need the old Containerfile and a second base-image build. A `light` variant becomes possible only if the mock terminal host gains a scriptable failure for `create_session()`; that extension is out of scope here.

### Why the long-name rule stays mostly unit-tested

`session_name()` is a pure function with a Rust unit test covering the pass-through, the boundary at 61 and 62 characters, and determinism. The standard spec exists to prove the failure it prevents (`local socket name length exceeds capacity of sun_path of sockaddr_un`) does not occur through the real attach, which the unit test cannot show.

## Spec scenario

Existing scenario, `embedded-workspace.spec.ts` (already updated; helper `liveHerdrSessions()` runs `herdr session list --json` through `podman exec` and returns running sessions other than `default`):

1. Create sandbox A and open its Dashboard. Assert `active_app` stays null and `liveHerdrSessions(nameA)` is empty: the terminal is not started eagerly.
2. Open the Terminal tab through `openTerminalPane`. `waitForTerminalAttached` waits for `data-status="attached"` on `[data-terminal='<name>']` and for the sandbox name to appear in the live session list: the start exec ran, the server is up and the SSH attach succeeded.
3. Assert the terminal view renders non-empty text and `liveHerdrSessions(nameA)` equals exactly `[nameA]`, then assert no terminal forward exists (`assertNoTerminalForward`).
4. Close the Terminal tab and assert the Dashboard is visible and the session list is still exactly `[nameA]`: detach is non-destructive.
5. Reopen the Terminal pane, wait for attach, assert the pane label is unchanged and the session list is still exactly `[nameA]`: the start script is idempotent and reattaches instead of starting a second server.

Existing scenario, `base-image-recipe.spec.ts`:

6. For the shipped Containerfile, assert the `HERDR_VERSION` argument is an exact semver, a `sha256sum -c` check precedes `chmod +x /usr/local/bin/herdr`, the mise pin is exact, and none of `releases/latest`, `@latest`, `mise.run` appears. For the two spike Containerfiles under `docs/features/sandbox-runtime-management/spike/mise/`, keep the zellij semver assertion. A separate assertion requires the `HERDR_SHA256` argument to be a 64-hex string; the `sha256sum -c` pattern alone asserts ordering only.

Written scenario, old-image error (its own spec, `herdr-multiplexer-missing.spec.ts`, so a failure does not poison the shared sandbox). The error state is the terminal view's `data-status="failed"` with `[data-terminal-error]` text and a `[data-terminal-retry]` button:

7. Create sandbox B. Close any terminal pane. Move the Herdr binary aside with `podman exec` against `LOCAL_CONNECTION`.
8. Open the Terminal tab for B through the UI. Assert the terminal view's error state shows the `MultiplexerMissing` message, which tells the user to recreate the sandbox from the project list, and that a Retry control is present. Assert no Herdr session exists for B (the exec exited before any server start). Use `captureDiagOnFailure()`.
9. Restore the binary (`mv` back), click Retry, and assert `waitForTerminalAttached(nameB)` succeeds: the failure is recoverable and the message is not sticky. Always restore in an `after` hook so a failed assertion does not leave the sandbox broken for later steps.

Written scenario, long name (`herdr-long-name.spec.ts`):

10. Create a sandbox whose name is 70 characters (a valid charset per `validate_name`, no length limit). Finding: 70 characters is accepted end to end by container creation, the `mio-sshd` attach and the workspace directory, so no lower cap was found and none is recorded; the spec uses 70.
11. Open the Terminal tab and wait for `data-status="attached"`. Assert `herdr session list --json` shows exactly one running non-default session, that its name is 61 characters, equals the first 52 characters of the sandbox name followed by `-` and 8 hex characters, and does not equal the sandbox name. The expected name is computed in the spec from the same rule (first 52 characters, hyphen, first 8 hex characters of the name's SHA-256, using node's `crypto`), so a change to the rule breaks the spec deliberately.
12. Close and reopen the tab and assert the same single session remains: the derived name is deterministic across attaches.
13. Assert the pane never reached `failed` and its text carries no `sun_path` capacity error. The spec reads the pane, not `mio.log`.

Cleanup for steps 7 to 13: each spec destroys its sandbox through the page-object helper as its last test, and its `after` hook force-removes the container; the old-image spec's `after` hook also moves the binary back first. No host path is created.

## De-risking spike results

The spike (2026-11-18, [spike/README.md](spike/README.md)) cleared: detached named-session start through one engine exec (median 467 ms, idempotent, container environment inherited); client attach, resize, SGR mouse focus and border drag, OSC 52 on selection, and detach persistence over russh; baked config suppressing onboarding and both network checks. It recorded no blocker that gates a spec. The two findings it raised, the 61-character session-name cap and the client-started server with a stripped environment, are handled in `src-tauri/src/terminal/mod.rs` and are why the long-name scenario and the idempotent-start assertion exist. What the spike did not run: wterm in the real webview, microsandbox, and a deployed sandbox. The attach through the app itself is now proven by the passing `embedded-workspace.spec.ts`.

## Gaps

- The two base-image build specs have not been run through wdio since the swap.
- The pane's rendered Herdr output is checked only as non-empty text; no assertion proves the frame is Herdr's UI rather than a shell prompt. A candidate is matching a stable Herdr sidebar string, deferred until the string is confirmed against the real renderer.
- No assertion covers Herdr panes inheriting the container's proxy variables and the workspace directory, which the spike showed is the failure the engine-exec start prevents. A candidate step: after attach, `podman exec` into the session through `herdr pane list --json` or read a pane's environment, and compare with the container's; deferred because the attach spec's sandbox is created without a proxy, so no proxy variable exists to compare, and pane-level introspection commands were not exercised in the spike beyond `pane list`.
- Phase D recorded results carry no measured figures (no first-frame time).

## Common Gotchas

| Gotcha | Cause | Fix |
|---|---|---|
| `liveHerdrSessions()` returns an empty list although the terminal attached | The helper swallows a JSON parse failure and returns `[]` (`podman exec ... herdr session list --json` ran with `check: false`) | When an attach assertion times out, run the same `podman exec` by hand and read its output before suspecting the app |
| The session list contains an extra entry | The `default` session always appears, with `running` false | Filter on `running` and exclude `default`, as the helper does |
| A spec that expects a session after a stop and start finds none | A container stop ends the Herdr server and its panes | Reopen the Terminal tab; the start exec recreates the server |
| The old-image step leaves sandbox B without Herdr | The assertion failed between the `mv` aside and the restore | Restore in an `after` hook, not inline |
| The recipe spec fails on the checksum argument | `PINNED_HERDR_SHA256` requires `ARG HERDR_SHA256=` followed by exactly 64 lowercase hex characters; `HERDR_CHECKSUM` separately asserts `sha256sum -c` precedes `chmod +x` | Paste the full lowercase digest from the release's checksum file |
| A long-name spec fails on the unexpected session name | The expected name must follow `session_name()` exactly: 52-character prefix, hyphen, 8 hex characters of the SHA-256 of the full sandbox name | Compute the expected name in the spec from the same rule; do not hard-code it |
| A first `standard` run after the bump takes many minutes | `BASE_IMAGE_VERSION` 8 triggers a base-image build that downloads the Herdr asset from github.com | Allow the build budget; an offline host fails at the download |
| A command reaches the developer's own Herdr | `herdr` run on the host talks to the API socket under `%APPDATA%\herdr` | Only run Herdr through `podman exec` against `LOCAL_CONNECTION` |
