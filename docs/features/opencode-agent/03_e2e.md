# OpenCode Agent E2E Plan

End-to-end coverage for the OpenCode agent (`docs/features/opencode-agent/02_dev.md`). Two WebdriverIO specs split by cost: a standard spec that proves install + provisioning + config-merge against a real container, and a heavy spec that proves the app-wide reverse forward actually bridges a container to the host inference server. Both drive the built debug app through `tauri-driver` and assert out-of-band with the `podman --connection mio-tests` CLI and host-filesystem reads, never trusting the UI alone.

## Specs

### `e2e/test/specs/opencode-agent.spec.ts` (standard suite)

Runs in the default `pnpm test` glob. No inference server, so it is the cheap half: it never loads a model. Mirrors `agent-setup.spec.ts` (the Claude Code analogue) for project lifecycle and diagnostics-on-failure.

Steps, in order (shared project, one `describe`):

- **No-agents baseline** — creates a project and asserts the Agents section shows "No agents installed." once `mise.toml` exists.
- **Install + provision** — installs OpenCode through the UI (`Add agent` → `install`), waits for the agent row, then asserts: `mise.toml` lists `opencode`; `mise exec -- opencode --version` prints a version (proves the self-contained binary install, no npm postinstall); and `<workspace>/opencode.json` is written with `$schema`, `provider["local-llm"]` (loader `@ai-sdk/openai-compatible`, `baseURL` = `http://host.containers.internal:51199/v1`, a non-empty `apiKey`, a non-empty `models` map from the catalogue), and top-level `model` = `local-llm/phi-4-mini-reasoning`.
- **Endpoint-down hint** — with no inference server running, asserts the row renders the `/models` "Start a model" hint link (the `agentProviderHint` page-object getter) rather than the provider-configured line or an error.
- **Merge, never clobber** — seeds an `opencode.json` carrying a user `model`, an unrelated `anthropic` provider, and a `theme`, then re-invokes `provision_opencode` through the webview command bridge. Asserts the user `model`, the foreign provider, and `theme` survive, while `provider["local-llm"]` and `$schema` are added.
- **Corrupt config is not overwritten** — writes invalid JSON, invokes `provision_opencode`, and asserts the call rejects *and* the file is left byte-for-byte unchanged.
- **Destroy** — removes the container and confirms it is gone.

### `e2e/test/specs/heavy/opencode-forward.spec.ts` (heavy suite)

Excluded from the default glob; run with `pnpm run test:heavy` or `pnpm run test:opencode-forward`. The only test that exercises the full reverse-forward bridge, so it needs both a running sandbox container *and* a loaded model (the tiny `MIO_TEST_MODEL` GGUF injected by `wdio.conf.ts`). Depends on the staged llama engine, like `heavy/local-llm.spec.ts`.

The single flow test:

- Creates and starts a sandbox container; asserts `host.containers.internal` is in the container's `/etc/hosts` (precondition for the baseURL ever resolving).
- Probes `host.containers.internal:51199/v1/models` from inside the container **before** inference starts and asserts no listener answers (no forward should exist yet).
- Navigates to `/models`, downloads + starts the test model, which creates the app-wide `inference-reverse` forward.
- Re-probes until the container gets `HTTP 200` with an OpenAI model-list body — the decisive assertion that the forward listens on the VM's `0.0.0.0` (a `127.0.0.1` bind would be invisible to the container) and dials the live host port.
- Stops inference and asserts the port stops answering — the forward must be torn down, not orphaned.
- Destroys the container.

The in-container probe is a raw HTTP/1.0 GET over bash's `/dev/tcp`, so the base image needs no `curl`/`wget`, and a torn-down forward surfaces as a non-zero exit with no `HTTP/1.` line — exactly the negative signal the post-stop assertion checks.

## Port constant

`51199` (`INFERENCE_VM_PORT`) is asserted literally in both specs. It must equal `sync::INFERENCE_VM_PORT` (Rust) and the `INFERENCE_VM_PORT` in `src/lib/agents/opencode.ts`; a drift between any of the three fails the baseURL assertion in the standard spec or the reachability assertion in the heavy spec.

## Common Gotchas

| Gotcha | Cause | Fix |
|---|---|---|
| Forward reachability test times out at HTTP 200 | The reverse forward bound the VM's `127.0.0.1`, or was never created | `forward_create_reverse` must bind `0.0.0.0`; the forward only exists while inference runs |
| In-container probe never connects, even with the forward up | `host.containers.internal` absent from the container netns | The spec asserts `/etc/hosts` up front; rootless podman adds the alias by default |
| Standard spec's hint assertion fails | An inference server was left running from a prior aborted run, flipping the row to "provider configured" | The standard spec starts no server; ensure `stop_inference` ran (the heavy spec's `after` hook does this) |
| `opencode --version` exits non-zero | OpenCode installed outside mise, so the binary is not on the mise shim path | Install via the catalogue `misePackages: ["opencode"]`; probe with `mise exec -- opencode` |
| Heavy spec skipped or fails at sidecar resolution | llama engine not staged next to the debug exe | Stage `src-tauri/binaries/llama` per `docs/features/local-llm/03_e2e.md` |
