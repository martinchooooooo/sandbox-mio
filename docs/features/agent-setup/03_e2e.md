# Agent Setup E2E Test Plan

Test plan for the agent setup feature built in `02_dev.md`. A spike was run on 2026-06-28 that proved the full Claude Code install + OAuth auth flow end-to-end inside a real sandbox container (see `01_ideas.md` Validation section). The spec described here automates the install pipeline and auth status display; the OAuth code exchange is explicitly excluded from the automated spec because it requires a human to authorize on claude.com and copy a one-time PKCE code — the spike serves as proof for that step.

## Goal

The spec must prove:

1. Clicking "Add agent → Claude Code" in the `SandboxItem` Agents panel invokes `install_agent` (Phase B), which calls `runtime.install()` per mise package and then `runtime.exec_in_container()` for the npm postinstall — the real `podman exec mise use` and `podman exec node install.cjs` commands against a live container.
2. After install, the `claude` native binary executes correctly inside the container via `mise exec`.
3. `get_agent_auth_status` (Phase B) correctly returns `authenticated: false` when no credential file exists, and `authenticated: true` with the correct email when credential files are pre-seeded into the container.
4. Clicking "Authenticate" causes `start_agent_auth` (Phase B) to spawn a `podman exec mise exec -- claude auth login` process inside the container with stdin piped — confirmed by the process appearing in the container's `/proc` tree.

A weaker test (e.g. checking only that `mise.toml` was updated without running `claude --version`) would fail to catch the postinstall step being skipped — the bug the spike discovered where mise's `--ignore-scripts=true` leaves the native binary absent.

## Existing Test Styles

All e2e tests use the same style: a real compiled Tauri app driven by WebdriverIO (`tauri-driver` + `msedgedriver`) against real Podman containers provisioned on the `mio-tests` connection. Tests read state from the filesystem and from `podman exec` output; they never mock Tauri commands or the Rust backend.

Existing specs and paths:

| Spec | Path | What it proves |
|---|---|---|
| Runtime management | `e2e/test/specs/runtime-management.spec.ts` | `install_package` → `mise use` → binary runs in container |

The new agent-setup spec belongs to the same style. It targets only `LOCAL_CONNECTION` (`mio-tests`) — no remote machine is needed.

- `e2e/test/pageobjects/project-row.component.ts` — `ProjectRow`: per-sandbox controls

## Chosen Approach

Spec file: `e2e/test/specs/agent-setup.spec.ts`.

Single Podman machine (`mio-tests`, `LOCAL_CONNECTION`). No remote machine required. The spec creates a fresh sandbox, drives the install through the UI, verifies the install via CLI, pre-seeds credential files via `podman exec`, navigates away and back to trigger `onMount` → `loadAgentStatuses`, then asserts the UI reflects the seeded state. The auth window launch test clicks "Authenticate", polls the container's `/proc` tree for the `claude auth login` process, then tears down.

`this.timeout(900000)` (15 minutes): `node@lts` downloads ~30 MB; `npm:@anthropic-ai/claude-code` and its native postinstall binary add another ~40 MB. These are one-time on a cold container; subsequent runs against a kept machine are faster but the ceiling must cover cold starts.

## Harness Changes

No new env vars. No new machines. No `wdio.conf.ts` changes.

The `before` hook in the spec creates the sandbox; the `after` hook destroys it with `podman rm -f` (best-effort, same pattern as `runtime-management.spec.ts`).

## Page Object Additions — `e2e/test/pageobjects/project-row.component.ts`

Add the following to the `ProjectRow` class. All selectors use text-based queries (no CSS class assumptions), consistent with the existing `button=install` pattern.

```ts
// The "Add agent" button in the Agents section.
get addAgentButton(): Element {
  return this.root.$("button=Add agent");
}

// The Install button next to `agentLabel` in the picker list.
agentInstallButton(agentLabel: string): Element {
  return this.root.$(`*=${agentLabel}`).$("../..").$("button=install");
}

// The "Authenticate" or "Re-authenticate" button for the named agent label.
agentAuthButton(agentLabel: string): Element {
  return this.root.$(`span=${agentLabel}`).$("..").$("button*=authenticate");
}

// The status span next to the agent label ("not authenticated" or an email address).
agentStatusText(agentLabel: string): Element {
  return this.root.$(`span=${agentLabel}`).$("..").$("span.text-muted-foreground, span.text-amber-600");
}

// Clicks Add agent, then clicks Install next to `agentLabel` in the picker.
async startAgentInstall(agentLabel: string): Promise<void> {
  const btn = await this.addAgentButton;
  await btn.scrollIntoView();
  await btn.click();
  await this.#clickButton(this.agentInstallButton(agentLabel));
}

// Waits until the agent row for `agentLabel` appears in the Agents section.
async waitForAgentRow(agentLabel: string, timeoutMs = 600000): Promise<void> {
  await browser.waitUntil(
    async () => (await this.root.$(`span=${agentLabel}`)).isExisting(),
    { timeout: timeoutMs, interval: 3000, timeoutMsg: `agent row for "${agentLabel}" did not appear` }
  );
}

// Waits until the status text next to `agentLabel` equals `text`.
async waitForAgentStatus(agentLabel: string, text: string, timeoutMs = 10000): Promise<void> {
  await browser.waitUntil(
    async () => (await this.agentStatusText(agentLabel).getText()) === text,
    { timeout: timeoutMs, interval: 500, timeoutMsg: `agent status for "${agentLabel}" did not become "${text}"` }
  );
}
```

## Spec Scenario — `e2e/test/specs/agent-setup.spec.ts`

```ts
describe("Agent setup — Claude Code", function () {
  this.timeout(900000);
  // ...
});
```

---

**Step 1 — Suite setup**

`before`: Verify `SANDBOX_WORKSPACE_ROOT` is set, compute `workspaceDir` and `manifestPath`. Open the projects page, create a project named `e2e-agents-<timestamp>`, wait for the row. The create timeout is 600000 ms (base-image build on cold machine).

`after`: `podman(LOCAL_CONNECTION, ["rm", "-f", projectName], { check: false })` — best-effort cleanup.

`afterEach`: Capture `.diag` on failure (identical to `runtime-management.spec.ts` pattern).

---

**Step 2 — Agents section visible, no agents**

Action: Open projects page, locate the sandbox row.

Assertion: `$("span=No agents installed")` exists inside the row, using `waitForExist`. Proves Phase E rendered the Agents section and the empty state.

---

**Step 3 — Install Claude Code through the UI**

Action: Call `row.startAgentInstall("Claude Code")`. Wait for the agent row with `row.waitForAgentRow("Claude Code", 900000)` — the install downloads node@lts + npm package + native postinstall binary.

Assertions (all via `podman exec` against `LOCAL_CONNECTION`, `{ check: true }`):

3a. `mise.toml` contains `node` and `npm:@anthropic-ai/claude-code`:

```ts
const manifest = fs.readFileSync(manifestPath, "utf8");
assert(manifest.includes("node"), `mise.toml does not list "node" after agent install. Contents:\n${manifest}`);
assert(manifest.includes("npm:@anthropic-ai/claude-code"), `mise.toml does not list claude-code. Contents:\n${manifest}`);
```

3b. `claude --version` runs inside the container and reports a version string. This assertion is the decisive proof that the postinstall step ran — without it `claude` exits with "native binary not installed":

```ts
const ver = podman(LOCAL_CONNECTION, [
  "exec", "--workdir", "/root/work", projectName,
  "mise", "exec", "--", "claude", "--version",
]);
assert(ver.includes("Claude Code"), `"claude --version" printed "${ver}". `
  + "This can happen when the npm-postinstall step was skipped, leaving the native binary absent.");
```

3c. The Agents panel shows "Claude Code" with "not authenticated":

```ts
await row.waitForAgentStatus("Claude Code", "not authenticated");
```

---

**Step 4 — Auth status: reflects pre-seeded credentials**

Pre-seed credential files inside the running container via `podman exec`:

```ts
const expiresAt = Date.now() + 365 * 24 * 60 * 60 * 1000; // 1 year from now
podman(LOCAL_CONNECTION, [
  "exec", projectName, "bash", "-c",
  `mkdir -p /root/.claude && `
  + `printf '%s' '{"claudeAiOauth":{"accessToken":"test","refreshToken":"test","expiresAt":${expiresAt}}}' `
  + `> /root/.claude/.credentials.json && `
  + `printf '%s' '{"oauthAccount":{"emailAddress":"e2e-test@example.com"}}' `
  + `> /root/.claude.json`,
]);
```

Navigate away then back to trigger `onMount` → `loadAgentStatuses`:

```ts
await browser.url("/");        // home page
await ProjectsPage.open();    // back to /projects — remounts SandboxItem components
await row.waitForDisplayed();
```

Assertions:

4a. The status text next to "Claude Code" shows the seeded email:

```ts
await row.waitForAgentStatus("Claude Code", "e2e-test@example.com", 15000);
```

4b. The button reads "Re-authenticate" (not "Authenticate"), proving the UI branched on `authenticated: true`:

```ts
const btn = await row.agentAuthButton("Claude Code");
await expect(btn).toHaveText(/re-authenticate/i);
```

This step proves `get_agent_auth_status` (Phase B) correctly reads `claudeAiOauth.expiresAt` and `oauthAccount.emailAddress` from the container filesystem via `podman exec cat`.

---

**Step 5 — Clicking Authenticate starts the auth command in the container**

Remove the credential files to reset to unauthenticated state, then navigate away and back:

```ts
podman(LOCAL_CONNECTION, ["exec", projectName, "bash", "-c",
  "rm -f /root/.claude/.credentials.json /root/.claude.json"]);
await browser.url("/");
await ProjectsPage.open();
await row.waitForDisplayed();
await row.waitForAgentStatus("Claude Code", "not authenticated");
```

Action: Click "Authenticate":

```ts
const authBtn = await row.agentAuthButton("Claude Code");
await authBtn.scrollIntoView();
await authBtn.click();
```

Wait 8 seconds for the process to start (mise exec startup + claude binary launch):

```ts
await browser.pause(8000);
```

Assert `claude auth login` appears in the container process list via `/proc` scan. The container has no `ps`, so scan via bash:

```ts
const procs = podman(LOCAL_CONNECTION, [
  "exec", projectName, "bash", "-c",
  "for f in /proc/[0-9]*/cmdline; do tr '\\0' ' ' < \"$f\" 2>/dev/null; echo; done",
], { check: false });
assert(
  procs.includes("claude") && procs.includes("auth") && procs.includes("login"),
  `No "claude auth login" process found in container after clicking Authenticate. `/proc scan:\n${procs}\n`
    + "This can happen when start_agent_auth did not spawn the process or the binary path is wrong."
);
```

This step proves `start_agent_auth` (Phase B) reaches the real `podman exec ... claude auth login` path. The spec does NOT complete the OAuth code exchange — that path is validated by the 2026-06-28 manual spike.

---

**Step 6 — Destroy cleans up**

Action: `await row.destroy()`.

Assertion: `podmanOk(LOCAL_CONNECTION, ["inspect", projectName])` returns false. Proves the running auth process does not prevent container removal (`podman rm -f` force-kills it).

## De-risking Spike Results

Spike run on 2026-06-28 against container `dfsdf` on `podman-machine-default`. Full results in `01_ideas.md` Validation section. Summary of what cleared relevant to this spec:

| Risk | Result | Command |
|---|---|---|
| `claude auth login` needs a TTY | Cleared. Runs with piped stdin, no `-t`. URL and prompt appear in captured stdout. | `podman exec --workdir /root/work dfsdf sh /tmp/auth_via_fifo.sh` |
| OAuth callback needs published port | Cleared. `redirect_uri` is `platform.claude.com` (server-side). No container port required. | URL inspection: `redirect_uri=https%3A%2F%2Fplatform.claude.com%2Foauth%2Fcode%2Fcallback` |
| Credential file paths | Cleared. `/root/.claude.json` (account) + `/root/.claude/.credentials.json` (tokens with `expiresAt`). | `podman exec dfsdf find /root -maxdepth 2 -name "*.json"` |
| Mise postinstall skip | **Blocker found** (feature fix, not test concern — fixed in Phase A). Mise's `--ignore-scripts=true` leaves native binary absent. Fixed by `run_npm_postinstall` calling `node install.cjs` explicitly. The spec in Step 3b catches a regression here. | Error: `"Error: claude native binary not installed."` after plain `mise use` |
| `claude --version` callable via `mise exec` | Cleared. After postinstall, `mise exec -- claude --version` prints `2.1.195 (Claude Code)`. | `podman exec --workdir /root/work dfsdf mise exec -- claude --version` |

No blockers remain. The spec is ready to write alongside the implementation.

## Sequencing

1. Implement Phases A–E (`02_dev.md`).
2. Write page object additions to `project-row.component.ts`.
3. Write `agent-setup.spec.ts`.
4. Run spec against a cold `mio-tests` machine to validate timeout ceilings.

The spec has no dependency on the auth window being fully driveable. Steps 2–4 (install + status display) can be validated before Step 5 (auth process launch) is integrated.

## Environment Notes

- `mio-tests` Podman machine must be provisioned (handled by `wdio.conf.ts` `onPrepare`).
- The `mio-tests-remote` machine is **not needed** by this spec.
- `SANDBOX_WORKSPACE_ROOT` is set by `wdio.conf.ts` to `~/.sandbox-mio-e2e`; the spec reads it for `manifestPath`.
- The mise base image must be staged on `mio-tests` before the first create — `ensureMiseBaseImage` in `wdio.conf.ts` handles this.
- A cold `mio-tests` machine with no cached layers will download node@lts (~30 MB) + claude-code npm package (~40 MB) + the native binary via postinstall. The 900000 ms timeout covers this on a slow connection.
- The spec does not require a Claude account or internet access beyond the container's outbound HTTPS for `mise use` downloads (the OAuth flow is not exercised).

## Common Gotchas

| Gotcha | Cause | Fix |
|---|---|---|
| Step 3b fails with "native binary not installed" after install appears to succeed | `run_npm_postinstall` in Phase A was not called or failed silently | Check that `install_agent` command sends `PostInstallStart`/`PostInstallDone` events and that `exec_in_container` did not return an error; look for the `install.cjs` path resolution step in agent logs |
| `waitForAgentRow` times out at 900000 ms | `node@lts` download stalled or `npm install` for claude-code timed out | Run `podman exec <name> mise exec -- node --version` manually to verify node installed; if absent, check the `install_agent` Channel for error events |
| Step 4a shows "not authenticated" despite pre-seeded credentials | `get_agent_auth_status` read the credential file before the navigate-away-and-back triggered `loadAgentStatuses` | Verify the `browser.url("/")` + `ProjectsPage.open()` round-trip causes a full `onMount`; check that `loadAgentStatuses` is called in `onMount` after `loadPackages` |
| Step 4a shows `null` instead of the seeded email | `get_agent_auth_status` did not parse `oauthAccount.emailAddress` from `/root/.claude.json` | Confirm `accountSourceFile` and `accountEmailJsonKey` params are passed correctly from the frontend catalogue descriptor to the Tauri command |
| Step 5 `/proc` scan finds no `claude` process | `start_agent_auth` spawned the process but it exited immediately (missing binary, wrong path, `mise exec` failed to find the tool) | Run `podman exec <name> mise exec -- claude --version` manually; if that fails, the postinstall from Step 3 has a regression |
| `browser.pause(8000)` in Step 5 is not enough | On a cold machine, `mise exec` tool resolution adds latency before the claude binary starts | Increase pause to 15000 ms; alternatively replace with a `browser.waitUntil` loop polling the `/proc` scan |
| Step 6 destroy hangs | `claude auth login` holds an open stdin pipe and ignores SIGTERM | `podman rm -f` sends SIGKILL; `after()` uses `{ check: false }` so a timeout here does not fail the suite |
| `agentAuthButton` selector fails because button text is "Authenticate" (not "Re-authenticate") | Selector uses `button*=authenticate` (case-insensitive substring); both forms match | No fix needed; but if the Svelte button text changes format, update the selector |
