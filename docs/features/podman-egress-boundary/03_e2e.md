# E2E Test Plan — Podman Egress Boundary

This document is the end-to-end test plan for the build described in [02_dev.md](02_dev.md): a proxied Podman sandbox sits on an internal network behind a dual-homed iron-proxy sidecar, which enforces `.mio/net-policy.json`, swaps secret placeholders, and feeds the traffic panel from its audit stream. The plan has two specs: a `standard` spec that proves the boundary on a real Podman machine, and a `light` companion for the editor's gating logic and failure paths. No spike has been run for this plan. The Phase A spikes in [spike/README.md](spike/README.md) proved the topology by hand on `podman-machine-default`, not through the app and not on the `mio-tests` machine; the open pre-spec check is listed under De-risking Spike Results.

## Goal

The `standard` spec must prove the boundary through the real application:

- **Create**: the `create_sandbox` command (`src-tauri/src/commands/sandbox.rs`) with `proxy: true` and an egress mode, driving `services::sandbox::create` (`src-tauri/src/services/sandbox.rs`): `ensure_proxy_image` and `create_podman_proxy` (`src-tauri/src/proxy/mod.rs`), `CliBackend::create` with `prepare_egress` (`src-tauri/src/backends/mod.rs`), then `apply_policy_and_inject_ca`, which runs `proxy::iron::apply_policy` (`src-tauri/src/proxy/iron.rs`).
- **Live apply**: the `apply_sandbox_policy` command (`src-tauri/src/commands/net_policy.rs`) from `NetPolicyEditor.svelte`, reloading the running sidecar through busybox `wget` against its management listener.
- **Secret swap**: `set_proxy_secret` (`src-tauri/src/commands/proxy.rs`) followed by the editor's re-apply, which materialises a secret file the sidecar reads.
- **Traffic record**: `watch_proxy_flows` (`src-tauri/src/commands/proxy.rs`) driving the audit ingest in `src-tauri/src/proxy/flowlog.rs` and `src-tauri/src/proxy/audit.rs`.
- **Teardown**: `destroy_sandbox`, ending in `remove_proxy` (`src-tauri/src/proxy/mod.rs`).
- **Real components**: the pinned `docker.io/ironsh/iron-proxy:0.56.0` image (`IRON_PROXY_IMAGE_DEFAULT` in `src-tauri/src/proxy/iron.rs`), the bundled Podman client, the `mio-tests` machine, and the base image's `curl`.

A weaker test would miss the following:

- **The `light` tier** proves the rendered config and the command round-trips only. It cannot show that raw sockets are unreachable, that the sidecar actually reloads instead of restarting, or that the real value reaches the upstream while the guest holds only the placeholder.
- **Unit tests** in `src-tauri/src/proxy/iron_config.rs` and `src-tauri/src/proxy/audit.rs` pin key names and row translation against Phase A fixtures. They prove nothing about iron-proxy 0.56.0 accepting a config rendered by the app, or about `podman logs` returning audit lines for a sidecar the app created.
- **A spec that only asserts a 403 for a denied host** passes even if the sandbox still has a direct route out. The boundary claim needs the direct-route check (scenario step 4).

## Chosen Approach

- **Tier: `standard`.** The boundary is a property of real Podman networking and the real iron-proxy binary, so no lighter tier can prove it. No large asset is downloaded: the iron-proxy image is 64 MB, so the spec does not belong in `heavy`. Choosing `standard` means the run takes the host lock and serialises against every other real-infra run on the machine.
- **Spec path**: `e2e/test/specs/standard/podman-egress-boundary.spec.ts`.
- **Topology**: one Podman sandbox on the `mio-tests` connection (`LOCAL_CONNECTION` in `e2e/lib/podman-connection.ts`), created with the proxy switch on from an imported workspace folder that already holds a policy. A pre-seeded policy is the only way to get a binding's placeholder stamped at create (Resolved Decision 7).
- **External hosts**: `postman-echo.com` (allowed; its `/headers` endpoint echoes request headers, which proves the swap at the upstream) and `example.com` (denied at first, then allowed by a live apply). Both are public internet dependencies; see Common Gotchas.
- **Guest commands**: `podman --connection mio-tests exec <sandbox> sh -c '<curl …>'` through `podman()` in `e2e/lib/podman-connection.ts`. A `podman exec` process inherits the container's create-time environment, so it carries `proxy_env`, the CA variables and the placeholder, exactly like a terminal pane.
- **Host paths**: every path derives from `APP_DATA_ROOT` and `WORKSPACE_ROOT` in `e2e/lib/run-identity.ts`. The sidecar state directory is `<APP_DATA_ROOT>/proxy/<sandbox>/`, and the applied snapshot is `<APP_DATA_ROOT>/net-policy/<sandbox>/applied.json`.
- **Secret value**: a per-run unique fake string (for example `e2e-peb-<timestamp>`), so the absence assertions in step 9 can never match a leftover from an earlier run.

### Prerequisites

- **Page objects**:
  - `e2e/test/pageobjects/projects.page.ts` gains an `enableProxy()` helper. It clicks the `data-proxy-toggle` switch in the create card's Advanced section, opening Advanced first as `chooseProvider()` does.
  - `e2e/test/pageobjects/workspace-dashboard.page.ts` gains Network-section helpers: add an allow rule, save the policy, store a secret value, and read the apply report. It also gains Traffic-section helpers that read `data-flow-row` and `data-flow-rejected-by`.
- **Stable selectors**: `NetPolicyEditor.svelte` has no data attributes on the rule-target input, the add-rule button, the secret-id input, the secret-value input or its save button. The current placeholders are localised `m.*()` strings, and the sidecar target placeholder is hard-coded English that the Paraglide pass will replace. Add `data-net-policy-target`, `data-net-policy-add-rule`, `data-secret-id`, `data-secret-value` and `data-secret-value-save` before writing the page-object helpers. No spec may select by placeholder text.
- **Image pull**: no `e2e/wdio.conf.ts` change is needed. The first proxied create of a fresh machine pulls the iron-proxy image through `ensure_proxy_image`, reported in the activity center. `createProject()` therefore gets the `PACKAGE_INSTALL` budget from `e2e/lib/timeouts.ts`, not the default `SUBPROCESS`.
- **Cleanup**: the spec destroys its own sandbox in its final step. An `after` hook also calls `destroy_sandbox` with `force: true` through `invokeCmd()` (`e2e/lib/mock.ts`, which works against the real backend too), so a failed run cannot leave a sidecar or an internal network on `mio-tests`.

## Spec Scenario

1. **Seed the workspace.** Create a temporary import folder holding `.mio/net-policy.json`. The policy has egress `allowlist`, one allow rule for `postman-echo.com`, and one secret binding (`secretId` per run, `envVar` `E2E_PEB_KEY`, hosts `postman-echo.com`, header `authorization`). Store no secret value yet.
2. **Create through the UI.**
   - Open Home with `ProjectsPage.open()`, call `ensurePodmanReady()`, `chooseProvider("podman")`, `useExistingFolderMode()`, `enableProxy()` and `chooseEgress("allowlist")`, then `createProject(name)`.
   - Assert the egress picker was visible only after `enableProxy()` (`data-egress-option`).
   - Assert the Podman hint `data-proxy-podman-hint` is shown.
   - `chooseEgress("allowlist")` is required: the dialog always sends its mode, and the default `open` would overwrite the seeded file's `allowlist`.
   - Call `row.waitForRunning()`. No Start click is needed: `inject_ca` (`src-tauri/src/proxy/mod.rs`) starts the sandbox during create to install the CA.
3. **Read back the topology through the CLI and the filesystem.**
   - `podman network inspect mio-proxy-<name>` reports `internal: true`.
   - `podman inspect <name>` lists only `mio-proxy-<name>` among its networks.
   - `podman inspect <name>-proxy` is running the iron-proxy image and is attached to both `mio-proxy-<name>` and `podman`.
   - `<APP_DATA_ROOT>/proxy/<name>/meta.json` records `engine` `iron-proxy`.
   - `applied.json` lists `E2E_PEB_KEY` in `guestEnv`.
   - In the guest, `printenv E2E_PEB_KEY` prints `mio-placeholder-e2e_peb_key`.
4. **Prove the boundary.**
   - From the guest, `curl --noproxy '*'` to the literal address `https://1.1.1.1/` fails with a non-zero exit and no HTTP code, since the sandbox has no route out.
   - `curl https://example.com/` through the proxy variables fails with a non-zero exit, since `example.com` is not on the allowlist.
5. **Prove that a binding without a value passes through.** From the guest, `curl -sS https://postman-echo.com/headers -H "Authorization: Bearer $E2E_PEB_KEY"` returns 200, and the echoed `authorization` header holds the placeholder. This proves Resolved Decision 15: a binding without a stored value is left out of the config, and the whole apply does not fail.
6. **Store the secret value through the editor.**
   - Open the sandbox's Dashboard and switch to the `network` section.
   - Assert `data-proxy-non-http-blocked` is shown and `data-proxy-legacy` is absent.
   - Enter the binding's secret id and the per-run value, then click the secret-value save button.
   - Assert `data-net-policy-apply-report` reads as applied with no missing variable.
   - Repeat the step-5 `curl`: the echoed header now holds the real value, and `printenv E2E_PEB_KEY` still prints the placeholder.
7. **Live apply without a restart.**
   - Record the sidecar's start time with `podman inspect <name>-proxy --format {{.State.StartedAt}}`.
   - In the Network section, add an allow rule for `example.com` and click `data-net-policy-save`. Assert the apply report appears and `data-net-policy-drift` is absent.
   - From the guest, `curl https://example.com/` now returns 200.
   - The sidecar's start time is unchanged, which proves a reload rather than a restart (Resolved Decision 13).
   - `.mio/net-policy.json` in the import folder now contains the `example.com` rule.
8. **Check the traffic record.**
   - Switch to the `traffic` section, which starts `watch_proxy_flows`.
   - Wait for a `data-flow-row` whose host is `postman-echo.com`, and for a row carrying `data-flow-rejected-by` for the `example.com` request from step 4.
   - Assert `<APP_DATA_ROOT>/proxy/<name>/flows.ndjson` and `audit.cursor` exist and were modified during this run.
9. **Check that the secret is held only by the sidecar.** Search for the per-run secret value in four places:
   - the import folder recursively;
   - `podman inspect` output for both the sandbox and the sidecar;
   - `flows.ndjson`;
   - `mio.log` under the run's app-data root.

   The value must appear in none of the four. It must appear only in `<APP_DATA_ROOT>/proxy/secrets.json` and in the sidecar's `secrets/E2E_PEB_KEY` file, which holds exactly the value's bytes with no trailing newline.
10. **Destroy.**
    - Destroy the sandbox through `row.destroy()` and wait with `row.waitForGone(COMMAND)`.
    - Assert that `<name>`, `<name>-proxy` and the `mio-proxy-<name>` network no longer exist, and that `<APP_DATA_ROOT>/proxy/<name>/` is gone.
    - Assert that `podman network exists podman` still succeeds: `remove_proxy` must never remove the default network.

### Light Companion

`e2e/test/specs/light/podman-egress-boundary-ui.spec.ts` covers the gating and failure logic that is awkward to provoke on real infrastructure, against the scripted Podman runner (`src-tauri/src/mockctl/mod.rs`). It is not the feature's proof.

- **Create dialog**: with Podman chosen, the egress picker is absent while the proxy switch is off and present once it is on.
- **Editor dialect**: on a proxied Podman sandbox, the ports input, the violation-action buttons and the `data-net-policy-reapply` block are absent, and `data-net-policy-sidecar-hint` is shown.
- **Apply report**: saving a binding whose secret has no stored value lists that binding's variable in `data-net-policy-apply-report`.
- **Unstamped binding**: a binding added after create shows `data-net-policy-unstamped` with an `export` line holding the placeholder.
- **Drift**: editing `.mio/net-policy.json` on disk shows `data-net-policy-drift`, and `data-net-policy-save` is enabled with no edit in the editor.
- **Rejected reload**: scripting `podman.exec` as `fail-once` surfaces the reload error in the editor. `config.yaml` under the state directory is byte-identical to its content before the save.
- **Legacy sidecar**: rewriting `meta.json` without `engine` shows `data-proxy-legacy` and no editor.
- **Audit translation**: scripting `podman.logs` with lines from `spike/fixtures/podman-logs-timestamps.txt` renders `data-flow-rejected-by` and `data-flow-would-block` rows.
- **Mock assumptions to confirm**:
  - The mock's tracked `podman.ps` reports an empty `Image`, which `is_sidecar` (`src-tauri/src/proxy/mod.rs`) must still classify as a sidecar.
  - `podman.exec` and `podman.network-*` must default to exit 0 with empty output (`default_output()` in `src-tauri/src/mockctl/mod.rs`).

## De-risking Spike Results

No spike has been run for this plan. On 2026-11-14 a read-only probe found the `mio-tests` machine stopped, so the following pre-spec checks are still open:

- `podman --connection mio-tests network inspect podman` must report the default network with DNS disabled, as Phase A found on `podman-machine-default` (Resolved Decision 3). A missing network, or one with DNS enabled, is a **feature fix**: implement the per-sandbox `mio-egress-<sandbox>` fallback of Resolved Decision 3. The spec should wait on that fix.
- The image `docker.io/ironsh/iron-proxy:0.56.0` is absent from `mio-tests`. Absence is expected: the first create pulls the image, and step 2 budgets for the pull.

Run both checks after `./build e2e` has provisioned and started `mio-tests`, and before writing the spec. Record the result here.

## Common Gotchas

| Gotcha | Cause | Fix |
|---|---|---|
| `createProject()` times out on the first proxied create of a run | `ensure_proxy_image` (`src-tauri/src/proxy/mod.rs`) pulls the 64 MB iron-proxy image into a fresh `mio-tests` machine before the sidecar starts | Pass the `PACKAGE_INSTALL` budget from `e2e/lib/timeouts.ts` to `createProject()` in `e2e/test/specs/standard/podman-egress-boundary.spec.ts` |
| A guest `curl` to an allowed host fails with a 403 or a refused CONNECT right after create | `apply_policy` did not run after `store.create`, so the sidecar still runs the deny-all bootstrap config (`02_dev.md`, Resolved Decision 18) | Read the `create_sandbox` apply stage in `mio.log` under the run's app-data root; `services::sandbox::create` (`src-tauri/src/services/sandbox.rs`) must reach `apply_policy_and_inject_ca` |
| The seeded allowlist becomes `open` after create | The create dialog always sends its egress mode, and the default `open` overwrites the imported `.mio/net-policy.json` mode in `prepare_egress` (`src-tauri/src/backends/mod.rs`) | Call `ProjectsPage.chooseEgress("allowlist")` after `enableProxy()` and before `createProject()` |
| `printenv E2E_PEB_KEY` is empty in the guest | The binding was added after `podman create`, and placeholders are stamped only at create (`02_dev.md`, Resolved Decision 7) | Seed the binding in the imported `.mio/net-policy.json` before `createProject()`, never through the editor afterwards |
| The traffic section shows no rows although guest requests succeeded | The audit ingest in `src-tauri/src/proxy/flowlog.rs` runs only while the traffic panel watches the sidecar | Switch the Dashboard to the `traffic` section before waiting on `data-flow-row`; the ingest reads from `audit.cursor`, so earlier requests still arrive |
| The step-5 or step-6 echo assertion fails with a connection error, not a wrong header | `postman-echo.com` is a public service outside the test's control | Re-run before investigating the app; if the outage persists, move both steps to `httpbin.org/headers`, which needs the same allow rule and binding host change |
| The live-apply step sees a changed sidecar `StartedAt` | `apply_policy` (`src-tauri/src/proxy/iron.rs`) started a stopped sidecar instead of reloading a running one, or something restarted the sidecar between steps | Confirm `<name>-proxy` is running before step 7; a restart on a rejected reload is forbidden by `02_dev.md`, Resolved Decision 13 |
| A Network-section helper finds no input after the Paraglide pass | The helper selected an input by its placeholder text, which the Paraglide pass replaces with a localised string | Select by the `data-net-policy-target`, `data-secret-id` and `data-secret-value` attributes in `src/routes/projects/NetPolicyEditor.svelte` |
| The step-9 secret-absence search matches in a file the run did not write | The secret value was reused across runs, so a leftover from an earlier run matched | Generate the secret value per run with a timestamp suffix |
| `podman network exists podman` fails after destroy and other containers lose networking | `remove_proxy` (`src-tauri/src/proxy/mod.rs`) removed the default `podman` network that the sidecar's external leg joins | `remove_proxy` must remove only `mio-proxy-<sandbox>`; treat a failed step-10 assertion as a feature bug, not a flake |
