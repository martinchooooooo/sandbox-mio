# Unified Sidebar Navigation E2E

This document is the end-to-end test plan for the app sidebar, the page-or-sandbox content area and the single sandbox header built in `docs/features/unified-sidebar-nav/02_dev.md` (frontend Phases A to F and the Rust constant of Phase G). The feature changes navigation chrome only, so the plan has two parts: one new `light` spec for the navigation rules, and the existing page objects and specs of all three tiers brought in line with the new shell. No spike was run; the first light run against the new shell (De-risking Results) served as one.

## Goal

The real code path the tests must prove:

- **Page navigation:** a sidebar entry (`button[data-nav]` in `src/lib/workspace/AppSidebar.svelte`) → `showPage` in `src/lib/workspace/navigation.svelte.ts` → the SvelteKit route change, `clearActiveSandbox` and the `hide_active_pane` command (`src-tauri/src/commands/panes.rs`) → the `workspace://state` echo folded by `src/lib/workspace/state.svelte.ts` → `src/routes/+layout.svelte` mounting the routed page only once no sandbox is in view.
- **Opening a sandbox:** the Home card's workspace button (`src/routes/projects/SandboxItem.svelte`) → `openSandbox(..., { restore: false })` → `watch_workspace_ports` plus `hide_active_pane` → Manage; the sidebar entry (`button[data-nav-sandbox]`) → `openSandbox(..., { restore: true })` → `restoreTarget` → `switch_pane` to the remembered pane, or `hide_active_pane` when Manage was the last view.
- **Pane survival:** a page shown over an active pane hides the pane through `hide_active_pane` and leaves it registered in the Rust `WorkspaceRegistry` (`src-tauri/src/workspace/mod.rs`) with its forward or chat attach stream alive.
- **Closing:** the header's close (`button[data-close-sandbox]` in `src/lib/workspace/SandboxHeader.svelte`) → `closeSandbox` → `close_workspace` → `close_app`, which activates the remaining sandbox's last pane as the neighbour; with no neighbour the content area returns to Home.
- **Rail:** the sidebar toggle → `set_panel_collapsed` → `workspace_layout()` with `NAVIGATION_PANEL_RAIL_W`, echoed back as `collapsed` and rendered as `aside[data-collapsed]`.

A weaker test fails to cover the following:

- **A URL check proves nothing.** The URL keeps the last page's path while a sandbox is in view and the page is unmounted (Resolved Decision 9), so a spec that reads `/projects` from the URL passes while Home is not showing. The page objects decide from the sidebar entry's `data-active` and from `main[data-home]`.
- **The `light` tier proves no pane geometry.** Under `MIO_MOCK_BACKEND=1` no Terminal or Agents webview pane can open (no forward), so the light spec uses the native chat, a Rust-registered pane without a webview, as its pane. Whether a real webview pane sits beside the 240px sidebar and below the 64px header is proven only by `e2e/test/specs/standard/embedded-workspace.spec.ts` against the overlay rectangle Rust reports.

## Chosen Approach

| Id | Tier | Spec path | Status | Proves |
|---|---|---|---|---|
| L1 | `light` | `e2e/test/specs/light/sidebar-navigation-ui.spec.ts` | Written, passing | Page navigation and highlighting, card versus sidebar restore, pane hidden behind a page and restored, one header at a time, rail, New sandbox focus, close and delete landing on Home, the close neighbour rule |
| S1 | `standard` | `e2e/test/specs/standard/embedded-workspace.spec.ts` | Updated, not run | Overlay rectangle at 240/48/64, Home hiding a real Terminal pane with its forward still connected, sidebar restoring the Terminal pane, Home unmounted while a sandbox is in view |
| — | all | every spec that drives Home, Models, Settings or a sandbox | Updated through the page objects; light run green, standard and heavy not run | The rest of the suite on the new shell |

- **Why L1 is `light`.** Every rule L1 checks is frontend view state plus `WorkspaceRegistry` bookkeeping, which the mock backend runs unmodified; the real-pane half of the same rules is S1. Decision rule 3 of `e2e/AGENTS.md` fits: L1 is the fast loop over UI and store logic, S1 the real proof.
- **Parallel worktrees.** The feature adds no host-global state (`02_dev.md`, Resolved Decision 12). L1 derives the chat's workspace path from `WORKSPACE_ROOT` (`e2e/lib/run-identity.ts`) and writes nothing else on the host.

### Harness and page objects

- `e2e/test/pageobjects/app.page.ts`: `navButton(href)`, `isPageShown(href)`, `showPage(href)` and `showHome()`. `goHome()` now shows Home; specs use it to force the next page visit to remount that page.
- `e2e/test/pageobjects/sidebar.page.ts` (new): the sandbox entries, `selectSandbox` (waits for the sandbox's header), `newSandbox`, and `setCollapsed` (waits for `data-collapsed`).
- `e2e/test/pageobjects/sandbox-header.page.ts` (new, replaces `workspace-switcher.page.ts`): tabs, close buttons, Start/Stop, Folder, the header's error line and running dot. Every action first brings its sandbox into view through the sidebar.
- `e2e/test/pageobjects/project-row.component.ts`: every card action and wait shows Home first, including `waitForGone`, which otherwise passes vacuously while a sandbox is in view.
- `e2e/test/pageobjects/projects.page.ts`: `open`, `chooseProvider` and `createProject` show Home first; `root` is `main[data-home]`.
- `e2e/test/pageobjects/workspace-dashboard.page.ts`: `waitForRendered` scopes to `[data-dashboard=<sandbox>]`, `folderButton` is dropped in favour of the sandbox header's, `destroyButton` matches the new "delete" label.
- No `e2e/wdio.conf.ts` change.

## Spec Scenario: L1 `sidebar-navigation-ui.spec.ts` (light, written)

Two sandboxes per run, `e2e-nav-a-<timestamp>` and `e2e-nav-b-<timestamp>`, created through Home. `after()` expands the sidebar and closes and destroys both through commands.

1. **Pages.** Choose Home, AI models, Accounts and logins, Settings, Guide and Home again in the sidebar; after each, exactly that entry is active, the URL path matches and no sandbox header exists.
2. **Card opens Manage.** Create A and B, open A from its card; A's header shows with Manage current, `main[data-home]` and every `li[data-sandbox]` are gone while the URL still reads `/projects`, no page entry is active, A's sidebar entry is, and the activity toggle is present.
3. **Switch in the sidebar.** Select B; B's Manage renders, exactly one header exists, only B is highlighted.
4. **Pane behind a page.** `open_agent_chat` for A brings A into view with the chat tab current. Choose AI models: `active_app` is null, the chat pane is still registered, no header and no chat view render. Select A in the sidebar: `active_app` returns to the chat pane and the chat reattaches (`data-connection="attached"`).
5. **Card ignores the last pane.** Open A from its card: Manage shows, `active_app` is null, the chat pane is still registered (Resolved Decision 2).
6. **Sidebar restores Manage.** Choose Settings, then A in the sidebar: Manage shows, because Manage was A's last view.
7. **Rail.** Collapse with the toggle: `workspace_state().collapsed` is true, page entries show no text and keep an `aria-label`; Settings and A remain reachable from the rail; expanding restores labels.
8. **New sandbox.** From A's view, New sandbox shows Home with the create card's name field focused.
9. **Close hands over to the neighbour.** Open the chat for B, then for A; close A from its header: B's chat becomes `active_app`, B's header shows, A has no panes (Resolved Decision 6).
10. **Close lands on Home.** Close B: `main[data-home]` shows, the Home entry is active, the URL is `/projects`, no panes remain.
11. **Delete lands on Home.** Delete B from its Manage "Delete sandbox" section: Home shows and B leaves the sidebar.

## Spec Scenario: S1 `embedded-workspace.spec.ts` (standard, updated, not run)

The existing scenario keeps its steps; the changes are:

- The layout constants are 240 (expanded sidebar), 48 (rail) and 64 (header).
- The Manage-tab step uses the sandbox header and asserts A's Home card is unmounted while A is in view. The old assertion that card labels hide at the 380px column is gone: Home cards no longer narrow.
- A new step shows Home over A's active Terminal pane: `active_app` is null, the Terminal pane stays registered with its forward `Connected`, the card carries no inline package or agent controls and keeps its labels; selecting A in the sidebar restores the Terminal pane.
- The collapse step also waits for `aside[data-collapsed=true]`.

## Other Specs Touched (by reading)

- `standard/agent-chat.spec.ts`: the restart step stops and starts the sandbox from the header, because the card's Start/Stop would show Home and unmount the chat whose `disconnected` state the step asserts.
- `standard/podman-startup-recovery.spec.ts`: step 1 leaves Home for Settings, since Home re-probes Podman only when it mounts.
- `heavy/activity-center.spec.ts`: comment only; `goHome()` now lands on Home.
- `light/onboarding-story-ui.spec.ts` and `light/activity-center-ui.spec.ts`: the top tab selector and bell wording replaced by the sidebar.

## De-risking Results

2026-11-13, first runs of the new shell:

- `./build e2e light`: 17 of 17 spec files and 68 tests passed on the first run with the updated page objects and L1, and again on a second full run. No product bug surfaced: every failure the old suite would have hit was a selector or an assumption in the page objects (top tabs, URL-based page checks, Home cards coexisting with the dashboard), fixed in the page objects rather than per spec.
- Risks cleared by L1: a page click with a pane active does not bring the sandbox back (Resolved Decision 10); the card and the sidebar restore different views (Resolved Decision 2); the chat's attach stream survives the view's unmount; `close_app`'s neighbour rule brings the other sandbox into view (Resolved Decision 6).
- The runs were made from a detached git worktree carrying the main tree's uncommitted changes, because orphaned `podman.exe`, `mutagen.exe` and `llama-server.exe` processes held files in the main tree's `src-tauri\target\debug\`. That is a test-environment concern, not a feature one.
- Not run: the `standard` and `heavy` tiers (S1 and every other real-infra spec touched above). S1 is the only proof that real webview panes sit at the new 240px offset; run it before marking the feature `implemented`.

## Common Gotchas

| Gotcha | Cause | Fix |
|---|---|---|
| A spec reports Home or Models open, then cannot find its cards or panels | The URL keeps the last page's path while a sandbox is in view and the page is unmounted | Decide with `isPageShown()`/`showHome()` in `e2e/test/pageobjects/app.page.ts`, never `browser.getUrl()` |
| `waitForGone` passes for a sandbox that still exists | No Home card exists at all while a sandbox is in view | `ProjectRow.waitForGone` shows Home first; keep that order in any new wait on a card |
| A header tab or Start/Stop is not found for a sandbox with open panes | Only the sandbox in view has a header | Use `sandbox-header.page.ts`, which selects the sandbox in the sidebar first |
| Stopping a sandbox from its Home card hides the pane a spec is watching | Every card action shows Home, which hides the active pane | Use the header's Start/Stop (`sandboxHeader.start`/`stop`) when the pane must stay on screen |
| A light spec cannot open a Terminal or Agents pane | Those panes need a Mutagen forward the mock backend does not create | Use the native chat (`open_agent_chat`) as the light tier's pane; leave webview panes to the standard tier |
| Home does not show the Start Podman screen after the machine stops | Home probes Podman only when it mounts | Leave Home for another page first, as `standard/podman-startup-recovery.spec.ts` does |
| `button=start`, `button=stop` or `button=folder` is not found in the sandbox header | The header hides those labels below a 44rem (704px) container width; the 1024px e2e window leaves the header 784px wide beside the expanded sidebar | Keep the window at its default size; a spec that shrinks it must select the header buttons by something other than text |
