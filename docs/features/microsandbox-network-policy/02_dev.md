# Microsandbox Network Policy: Build Plan

This document is the build plan for securing microsandbox-provider sandboxes' outbound traffic with microsandbox's own host-side network stack, and for chaining a mitmproxy sidecar microsandbox VM behind it so the traffic viewer works for microsandbox sandboxes. It continues `docs/features/microsandbox-network-policy/01_ideas.md` and supersedes it wherever the two disagree. The six user decisions of 2026-11-02 (`01_ideas.md`, Resolved Decisions) are carried forward unchanged; the open items `01_ideas.md` left for this document are resolved below. Status: every phase (A–H) is implemented; the light spec `e2e/test/specs/light/microsandbox-network-policy-ui.spec.ts` passes (2026-11-02, all four cases), and the i18n pass awaits approval. The four spike records in `docs/features/microsandbox-network-policy/spike/` (01 egress baseline, 02 secrets, 03 chained proxy, 04 msb mitm sidecar) are the evidence base; every `msb` flag named here was exercised there unless a phase marks it "verify". Relevant code: `src-tauri/src/provider/msb.rs`, `src-tauri/src/provider/types.rs`, `src-tauri/src/provider/mod.rs`, `src-tauri/src/proxy/`, `src-tauri/resources/mitm_flowlog_addon.py`, `src-tauri/src/services/sandbox.rs`, `src-tauri/src/backends/mod.rs`, `src-tauri/src/machine/msb.rs`, `src-tauri/src/mockctl/`, `src/routes/projects/CreateSandboxItem.svelte`, `src/routes/projects/ProxyPanel.svelte`, `src/routes/projects/TrafficPanel.svelte`, `src/lib/agents/`.

## The Concrete Model

**Three independent switches per microsandbox sandbox.** Egress mode (`open` by default, `allowlist` opt-in), secret bindings (zero or more), and the traffic viewer (off by default, opt-in) are independent. All three are rendered into one `msb create` argv because microsandbox fixes network rules at create time; changing any of them except a secret value means recreating the sandbox around its preserved workspace volume (Phase G).

**One shared, provider-neutral policy file.** `<workspace>/.mio/net-policy.json` holds the egress mode, an ordered rule list, the strict-hostname flag, secret bindings (secret id, guest variable name, hosts, substitution positions — never a value), the violation action, and an agent-facing deny message. A new shared module, `src-tauri/src/net_policy.rs`, owns the schema, `load`/`save` through `src-tauri/src/mio_files.rs`, validation, and the static starter base list. It is a plain file module like `mio_files.rs`, not a subsystem, so `backends`, `proxy` and `services` may all use it. `proxy-network-policy` adopts the same file for Podman (cross-feature dependency below).

**Provider seam.** `InstanceSpec` (`src-tauri/src/provider/types.rs`) gains `egress: Option<EgressPolicy>`, the provider-neutral rendering input built from the policy file plus an optional chained-proxy descriptor. `MsbProvider::create_instance` (`src-tauri/src/provider/msb.rs`) hands it to a new translator, `src-tauri/src/provider/msb_policy.rs`, which emits `--net-default-egress`, `--net-rule`, `--net-strict`, `--tls-intercept`, `--secret`, `--secret-violation-action`, the deny-message flag, `--proxy`, `--socks5-username`, `--socks5-password-env` and `--tls-upstream-ca-cert`. `PodmanProvider::create_instance` (`src-tauri/src/provider/mod.rs`) rejects `Some(egress)` until `proxy-network-policy` gives Podman an enforcement path. `ProviderCapabilities` gains `egress_policy` (true for microsandbox only).

**Secret values travel only in the spawned `msb` child's environment.** A new `StartEnvSource` trait (declared in `src-tauri/src/provider/types.rs`, implemented by `services::start_env::AppStartEnv` in a new `src-tauri/src/services/start_env.rs`, injected into `MsbProvider` at construction) resolves, per sandbox name, the environment every start-capable `msb` call needs: each bound secret's value from `<app_data_root>/proxy/secrets.json` (`proxy::load_secrets`, `src-tauri/src/proxy/mod.rs`) and, when the viewer is on, the SOCKS5 password. `ProcessRunner` (`src-tauri/src/process/types.rs`) gains `run_with_env` so the value reaches `msb` through the `ProcessRunner` seam without ever entering argv, the app's own environment, logs, or any guest-visible file. Which variables a sandbox needs is read from the applied-policy snapshot `<app_data_root>/net-policy/<sandbox>/applied.json`, written immediately before `msb create`.

**Chained viewer = a second microsandbox VM.** When the viewer is on, `proxy::create_proxy` (`src-tauri/src/proxy/mod.rs`) creates `<sandbox>-proxy` through `MsbProvider::create_sidecar`: the pinned `MITMPROXY_IMAGE_DEFAULT` image, `msb pull`ed through `MsbProvider::pull_image`, launched with `--script start=<mitmdump argv>` plus `--init /.msb/scripts/start`, `-p 127.0.0.1:<hostport>:1080`, `--mount-dir` for addons (read-only), flows (read-write) and the mitmproxy confdir (read-write), and microsandbox's default egress. The agent sandbox gets `--tls-intercept --proxy socks5://127.0.0.1:<hostport> --socks5-username mio --socks5-password-env MIO_SOCKS_PASSWORD --tls-upstream-ca-cert <certs>/mitmproxy-ca-cert.pem`. Enforcement stays in microsandbox; mitmproxy only observes. `mitm_addon.py` is never mounted for microsandbox, because microsandbox owns secret injection. `proxy::flowlog::watch_flows` (`src-tauri/src/proxy/flowlog.rs`) and `TrafficPanel.svelte` run unchanged against the sidecar's flow log.

**Create sequence (microsandbox, viewer on, allowlist).** `services::sandbox::create` (`src-tauri/src/services/sandbox.rs`): ensure base image → `ensure_proxy_image` on the microsandbox provider → `create_proxy` (allocate port and password, write addons/htpasswd/flows dirs, create and start the sidecar, wait for the CA, probe SOCKS5 readiness) → `store.create` (resolve the workspace, load or seed `.mio/net-policy.json`, write `applied.json`, build `InstanceSpec.egress`, `msb create` with the start environment) → write the secret-host marker file and restart the sidecar if any binding exists → runtime init → start → Mutagen session. No CA injection step: the guest already trusts microsandbox's own interception CA (`spike/01_egress-baseline.md`, Item 1).

## Resolved Decisions

User decisions of 2026-11-02 (settled; restated with their concrete mechanism):

1. **Upgrade sequencing** — Phase A ships the msb 0.6 → 0.7 code upgrade first. `MsbMachineManager::readiness` (`src-tauri/src/machine/msb.rs`) gains a minimum-version check against `MIN_MSB_VERSION = 0.7.12`, the only version the spikes validated; a lower version reports not-ready through a new `msb-version` setup step whose copy tells the user to run `msb self update` from a copy of `msb.exe`. The app never runs `msb self update` itself (Decision 14).
2. **Mitmproxy placement** — a per-sandbox sidecar microsandbox VM. `MsbProvider::create_sidecar` and `pull_image` are implemented (Phase E); `SidecarSpec` gains `publish`, a `--script`/`--init` mapping of `command`, a force-stop path (`MachineProvider::stop_sidecar`), and a readiness descriptor (`SidecarReadiness`). `create_network`/`remove_network` stay unsupported on `MsbProvider`. The sidecar keeps microsandbox's default `allow@public` egress, broader than an allowlisted agent, because it runs no agent code and a deny default breaks its DNS (`spike/04_msb-mitm-sidecar.md`, 6d).
3. **Default egress** — `open`. A new sandbox with no `.mio/net-policy.json` and no dialog choice gets no `--net-*` flags at all, which is microsandbox's own `allow@public` default.
4. **Starter allowlist** — the static base list lives in `net_policy::STARTER_BASE_HOSTS` (`src-tauri/src/net_policy.rs`); each `AgentDescriptor` (`src/lib/agents/types.ts`, values in `src/lib/agents/catalogue.ts`) gains `apiHosts: string[]`. The starter is applied only when the user picks allowlist mode. Location refinement: `01_ideas.md` named `provider/msb_policy.rs` for the base list; because the policy file is shared with Podman, the list moves to the provider-neutral `net_policy.rs`, and `msb_policy.rs` is only the argv translator.
5. **Viewer is a separate opt-in** — `create_sandbox`'s existing `proxy: Option<bool>` argument keeps meaning "viewer on"; egress mode is a new, independent `egress` argument (Phase D).
6. **One shared `.mio/net-policy.json`** — schema in Decision 12. Cross-feature dependency: `proxy-network-policy` must replace `.mio/proxy-policy.json` with this file in its Phase B; `docs/features/proxy-network-policy/02_dev.md` is not edited here.

Open items `01_ideas.md` left for this document:

7. **Sidecar proxyauth password exposure via `msb inspect`** — the `--script` body carries `--proxyauth @/addons/htpasswd`, a path only. `proxy::create_proxy` writes `<state>/addons/htpasswd` containing `mio:{SHA}<base64 sha1 of password>` into the read-only addons mount; the plaintext password lives only in `<state>/meta.json` under `<app_data_root>` and in the agent `msb` child's environment. Needs verification in Phase F: that mitmproxy 11.1.3's `--proxyauth @file` accepts a `{SHA}` htpasswd entry and that `msb inspect <sidecar> --format json` shows no password. Fallback if `{SHA}` is rejected: a bcrypt entry; if `@file` is unusable, `--proxyauth "mio:$(cat /addons/proxyauth)"` with the plaintext file in the read-only mount, which still keeps the value out of microsandbox's config.
8. **Published-port allocation and collision handling** — `proxy::allocate_socks_port` binds `127.0.0.1:0` and returns the OS-assigned port, mirroring `allocate_ephemeral_port` in `src-tauri/src/network/mod.rs` (duplicated, because subsystems never depend on each other). `ProviderError::PortInUse` is raised by `MsbProvider` and `create_proxy` retries with a fresh port up to three times. The port is persisted in `<state>/meta.json`, because the agent's `--proxy` URL is fixed at create; a later sidecar start that fails with `PortInUse` surfaces "proxy port taken — re-apply the network settings to recreate" and leaves recovery to Phase G's recreate. Verified on 0.7.12 (Phase E): `msb create -p` on a taken port exits 0 with empty stderr, and the only signal is a `published TCP port listener failed ... (os error 10048)` line in `<msb home>/sandboxes/<name>/logs/runtime.log` after that start's `sandbox starting` line. `MsbProvider` therefore reads that log after a sidecar create and after every start (`<msb home>` is `MSB_HOME`, else `%USERPROFILE%\.microsandbox`); a sidecar create with a failed bind is removed and returns `PortInUse`. A stopped sidecar releases its port, and `msb start` binds it again.
9. **Shell-join and quoting layer for `SidecarSpec.command`** — `msb_policy::script_body(&[String])` POSIX-single-quotes every argv element with the existing `shell_quote` (`src-tauri/src/provider/msb.rs`), joins with spaces, prefixes `exec ` so mitmdump replaces the shell, appends ` >/flows/mitmdump.log 2>&1` (spike 04 Item 2: mitmdump's console is otherwise invisible under `--init`), and starts with a `#!/bin/sh` line. The body is passed as one argv element (`start=<body>`) to `--script-raw`, not `--script`, so no host shell is involved. Verified on 0.7.12 (Phase E): `--script` decodes `\'` and `\\` escapes, so `shell_quote`'s `'\''` arrives as `'''` and the script fails `Unterminated quoted string`, and doubling the backslashes does not survive either; `--script-raw` writes the body byte-for-byte as an executable `/.msb/scripts/start`. `msb inspect` exposes no script fields.
10. **`secretInjected` for microsandbox** — derived from host bindings: `proxy::write_secret_hosts` writes `<state>/addons/rules.json` as one `{host, path_prefix: ""}` entry per host of every secret binding in the applied policy. `mitm_flowlog_addon.py`'s existing `_secret_injected` matcher then marks rows to those hosts with no addon change. Semantics are "a secret is bound to this host", an over-approximation: microsandbox substitutes only where the placeholder appears in a listed position, which mitmproxy cannot observe without the value.
11. **Per-agent field location** — `apiHosts: string[]` on `AgentDescriptor` in `src/lib/agents/types.ts`, frontend-only, following `src/AGENTS.md`'s "extend the catalogue file rather than branching on names". The frontend passes the union of all catalogue agents' `apiHosts` to `starter_net_policy`; Rust never reads the catalogue.
12. **Shared `.mio/net-policy.json` schema** (`net_policy::NetPolicy`, camelCase JSON): `version` (1); `egress` (`open` | `allowlist`, default `open`); `rules` (ordered; each has `action` `allow`|`deny` and exactly one target: `host` — exact name or `*.suffix` with at least two labels — or `cidr` or `group` (`public`|`private`|`host`); optional `protocol` `tcp`|`udp`; optional `ports`, a list of numbers or `a-b` ranges); `strictHostnames` (default true); `secrets` (each: `secretId`, `envVar` matching `[A-Z_][A-Z0-9_]*`, `hosts` exact names only, `headers` default `["authorization"]`, `query` and `body` booleans); `violationAction` (`block`|`block-and-log`|`block-and-terminate`, default `block-and-log`); `denyMessage` (optional string); `interactive` (optional boolean, reserved for `proxy-network-policy`'s Podman approval mode, rejected for microsandbox by validation). Rules are first-match-wins in file order; the `egress` mode is the fallback. Mapping for `proxy-network-policy`: its `PolicyMode::Off` is `open` with no rules; `Static` is any rule list; `Interactive` is `interactive: true`; its `defaultAction` `allow`/`deny` is `open`/`allowlist`; its exact-host rules are `host` rules.

New decisions made while planning (recommended defaults; the user should confirm 13–16):

13. **Starter hosts come from every catalogue agent, not only installed ones.** Rationale: an allowlist edit costs a recreate, and the catalogue holds three agents. Seed values (each "verify in Phase D" by running the agent under allowlist): `claude-code` → `api.anthropic.com`, `console.anthropic.com`, `claude.ai`, `statsig.anthropic.com`; `opencode` → `models.dev`, `opencode.ai`; `pi` → none (its local LLM is reached through the reverse forward, which is not egress, `spike/01_egress-baseline.md`, Item 4). Base list: `registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org`, `github.com`, `api.github.com`, `codeload.github.com`, `*.githubusercontent.com`, `nodejs.org`, `mise.jdx.dev`, `mise-versions.jdx.dev`, each `tcp` port 443.
14. **No automated `msb self update`.** The app reports the version gap and shows the copy-then-update instructions; automating the copy-to-temp update is deferred (`04_improvements.md`). Rationale: microsandbox is a system-installed prerequisite the app has never modified.
15. **Open mode with deny rules is rendered, not refused.** `open` plus any rule renders `--net-default-egress deny`, the rules in order, then a trailing `allow@public`, reproducing microsandbox's implicit default after the user's rules. Needs verification in Phase B: that microsandbox evaluates `--net-rule` tokens first-match in argv order (spike 01 saw `inspect` list them as "ordered rules", but precedence was not tested). If precedence differs, validation refuses deny rules in open mode for microsandbox.
16. **Secret value rotation applies at the next start, not live.** Microsandbox re-reads values at every start (`spike/02_secrets.md`, Item 4), so `set_proxy_secret` needs no extra call; live rotation through `msb modify --secret` is deferred (`04_improvements.md`).

Further settled points:

17. **A bound secret with no stored value fails the call.** `AppStartEnv::env_for` returns an error naming the secret id instead of omitting the variable, so `msb` can never fall back to a same-named variable inherited from the app's own environment.
18. **The applied snapshot, not the workspace file, drives start environments.** The workspace file can be edited after create; microsandbox keeps the create-time bindings, so `applied.json` records what the sandbox actually runs with, and `ProxyPanel.svelte` shows "changes pending — re-apply to recreate" when the workspace file differs from it.
19. **Flow-log and rules paths become environment-overridable in the addon.** `mitm_flowlog_addon.py` reads `MIO_FLOWS_PATH` and `MIO_RULES_PATH` with the current `/addons/...` values as defaults, so the Podman path is untouched and the microsandbox sidecar uses `/flows/flows.ndjson` on a directory mount, the truncate-verified form (`spike/04_msb-mitm-sidecar.md`, 2c). The script body sets both variables before `exec mitmdump`.
20. **Startup sweep is worktree-scoped for microsandbox sidecars.** `proxy::sweep` removes a microsandbox `<base>-proxy` only when `<app_data_root>/proxy/<base>/meta.json` exists in this app's data root and `<base>` is not live. The msb store is per-user and host-global, so an unscoped sweep in one worktree's app could remove another run's sidecar during that run's create window (the sidecar exists before its agent).

## Implemented: Phase B — shared policy model and the msb argv translator

- `src-tauri/src/net_policy.rs` (new; declared in `src-tauri/src/lib.rs` beside `mio_files`): `NetPolicy`, `NetRule` (optional `host`/`cidr`/`group` fields, exactly one required by validation), `PortSpec`, `SecretBinding` per Decision 12. The small value enums (`EgressMode`, `RuleAction`, `NetGroup`, `NetProtocol`, `ViolationAction`) are declared once with serde in `src-tauri/src/provider/types.rs` and re-exported by `net_policy`, so the provider module never depends on `net_policy`; `POLICY_FILE = "net-policy.json"`; `load(workspace_path) -> Result<NetPolicy, NetPolicyError>` (absent file → default open policy), `save(workspace_path, &NetPolicy)` via `mio_files::mio_path`/`write_pretty`; `validate(&NetPolicy, ProviderCapabilities)` (host syntax, suffix depth, CIDR parse, port ranges, `envVar` pattern and uniqueness, reserved names `PATH`, `HOME`, `MIO_SOCKS_PASSWORD`, any `MSB_` prefix, secret hosts exact and — in allowlist mode — covered by an allow rule, `interactive` refused when the provider is microsandbox); `STARTER_BASE_HOSTS` and `starter(extra_hosts: &[String]) -> NetPolicy` (allowlist mode, base hosts plus deduplicated extra hosts, each `tcp` 443); `to_egress(&NetPolicy, Option<ChainedProxy>)`; and Phase C's `AppliedPolicy { policy, chainedProxy }` snapshot with `write_applied`/`read_applied`/`remove_applied`.
- `src-tauri/src/provider/types.rs`: `EgressPolicy { mode, rules, strict_hostnames, secrets: Vec<SecretBindingSpec>, violation_action, deny_message, proxy: Option<ChainedProxy> }` and `ChainedProxy { host_port, username, password_env, upstream_ca_path }`, provider-neutral mirrors that `net_policy` converts into (the provider module never reads files). `InstanceSpec` gains `egress: Option<EgressPolicy>`. `ProviderCapabilities` gains `egress_policy: bool` (serialised `egressPolicy`).
- `src-tauri/src/provider/msb_policy.rs` (new): `render(&EgressPolicy) -> Vec<String>`. Rules: open with no rules, no secrets and no proxy → empty argv; open with rules → `--net-default-egress deny`, rules, trailing `--net-rule allow@public` (Decision 15); allowlist → `--net-default-egress deny` plus rules; never `allow@dns` (`spike/01_egress-baseline.md`, "0.7.12 Differences"); `--tls-intercept` whenever the mode is allowlist, any rule exists, any secret exists, or a proxy is chained; `--net-strict=false` only when `strict_hostnames` is false; one `--secret ENV:<options>@h1,h2` per binding, options comma-joined from `headers=[a,b]` (or `no-headers`), `query`, `body` (syntax read back through `msb inspect` on 0.7.12); `--secret-violation-action` only when a secret exists and the action is not the default; one `--net-rule` per protocol/port-range pair (a rule with ports but no protocol renders a `tcp` and a `udp` token); proxy flags per The Concrete Model. `msb create --help` on 0.7.12 has no deny-message flag (only the undocumented `--net-conf` file), so `denyMessage` is carried in `EgressPolicy` but not rendered (`04_improvements.md`, "Agent-facing deny message"). `SOCKS_PASSWORD_ENV = "MIO_SOCKS_PASSWORD"` and `SOCKS_USERNAME = "mio"` constants. Unit tests cover every branch and assert no rendered token ever contains a secret value.
- `src-tauri/src/provider/msb.rs`: `create_instance` appends `msb_policy::render` output after the labels when `spec.egress` is `Some`; `capabilities()` sets `egress_policy: true`. The existing refusal of `spec.network`/`spec.env` stays.
- `src-tauri/src/provider/mod.rs`: `PodmanProvider::create_instance` returns `ProviderError::CommandFailed` for `Some(egress)`; `capabilities()` sets `egress_policy: false`.
- `src/lib/providers.ts`: `ProviderCapabilities` gains `egressPolicy: boolean`.
- Verified on 0.7.12: with `deny@registry.npmjs.org:tcp:443` ahead of `allow@registry.npmjs.org:tcp:443`, the guest cannot resolve the name while an allowed control host returns 200, so rules are first-match in argv order and Decision 15 stands.

## Implemented: Phase C — start-environment plumbing and the mock call journal

- `src-tauri/src/process/types.rs`: `ProcessRunner::run_with_env(&self, args, env: &[(String, String)])` with a default implementation that delegates to `run` when `env` is empty and returns `io::ErrorKind::Unsupported` otherwise, so a runner that cannot carry environment never drops a secret silently. `SystemMsbRunner` overrides it in `src-tauri/src/process/mod.rs` by setting the pairs on `msb_command()` before `run_capturing_via_files`.
- `src-tauri/src/provider/types.rs`: `StartEnvSource` trait, `fn env_for(&self, instance: &str) -> Result<Vec<(String, String)>, ProviderError>`; documented contract: an instance with no applied snapshot gets an empty list (sidecars, pre-feature sandboxes). `NoStartEnv` is the empty implementation the provider unit tests use.
- `src-tauri/src/provider/msb.rs`: `MsbProvider` gains `start_env: Arc<dyn StartEnvSource>`; `default_msb_provider` and `default_registry` (`src-tauri/src/provider/mod.rs`) take it. A private `run_starting(name, argv)` calls `run_with_env` with `start_env.env_for(name)` and is used by `create_instance`, `start` and `exec`; `exec_command_inner` (shared by `exec_command` and `exec_piped`) sets the same pairs on its `Command`, because `msb exec` on a stopped sandbox is an implicit start (`spike/02_secrets.md`, Item 4). `exec_command` returns a `Command` and cannot fail, so an `env_for` error there is logged and the variables are left out (the implicit start then fails closed); `exec_piped` checks `env_for` first and returns the error. `run`'s argv logging is unchanged and never sees the environment.
- `src-tauri/src/services/start_env.rs` (new): `AppStartEnv { app: AppHandle }` implementing `StartEnvSource`: reads `<app_data_root>/net-policy/<instance>/applied.json`; for each binding, the value from `proxy::load_secrets`, failing on a missing value (Decision 17); when the snapshot records a chained proxy, the password from `<app_data_root>/proxy/<instance>/meta.json` under `MIO_SOCKS_PASSWORD`. Snapshot helpers `write_applied`/`read_applied`/`remove_applied` live in `net_policy.rs`, with the path resolved through `crate::paths::app_data_root` so `MIO_APP_DATA_DIR` isolates it per worktree.
- `src-tauri/src/bootstrap.rs`: `register_state` constructs `AppStartEnv::new(app.handle().clone())` and passes it into `provider::default_registry`.
- `src-tauri/src/mockctl/`: `ScriptedMsbRunner` overrides `run_with_env` (and `run` delegates to it). `MockDirector` gains a call journal of `RecordedCall { key, argv, env_names }` for every scripted `msb` call (environment variable names only, never values), exposed by a new `mock_calls(key)` command in `src-tauri/src/commands/mockctl.rs`, registered in `src-tauri/src/commands/mod.rs`, and wrapped as `mockCalls(key)` in `e2e/lib/mock.ts`; `mock_reset` clears it. Rationale: light specs must assert the rendered `msb create` argv and that values never reach argv, which no existing mock surface exposes.
- Unit tests in `src-tauri/src/provider/msb.rs`: a fake `StartEnvSource` returning one pair; `create_instance`, `start` and `exec` all record its name in the journal; an `env_for` error aborts before any `msb` call.

## Lifecycle and Cross-Cutting Concerns

**State locations.** `.mio/net-policy.json` (workspace; definitions only, visible to the guest through Mutagen sync, so never a value). `<app_data_root>/net-policy/<sandbox>/applied.json` (what the sandbox was created with). `<app_data_root>/proxy/secrets.json` (values, app-global, existing). `<app_data_root>/proxy/<sandbox>/` (sidecar state: `meta.json` with provider, port and SOCKS password; `certs/` holding the CA private key; `addons/`; `flows/`). Every path resolves through `crate::paths::app_data_root` (`src-tauri/src/paths.rs`), which honours `MIO_APP_DATA_DIR`.

**Cleanup order.** Destroy removes the agent instance, then `applied.json`, then the sidecar (`remove_proxy_if_present`), then the proxy state directory. Turning the viewer off removes the agent before the sidecar, because a stopped sidecar makes the agent fail closed but never bypass (`spike/04_msb-mitm-sidecar.md`, 6a). Recreating the sidecar must reuse its `certs/` directory: the agent's `--tls-upstream-ca-cert` points at that CA.

**State derivation.** Viewer enablement stays derived from `<sandbox>-proxy`'s presence (`docs/features/network-proxy/02_dev.md`, Resolved Decision 3), now looked up on the provider `meta.json` names. Egress mode and bindings are read from `applied.json`; drift is the workspace file versus `applied.json`.

**Secret handling invariants.** A value never appears in argv, `--env`, `.mio/`, `mio.log`, the flow log, or a guest file. Values exist in plaintext in `secrets.json`, in the spawned `msb` child's environment, and in flight inside the sidecar's mitmproxy process (substitution precedes the upstream leg, `spike/03_chained-proxy.md`, Item 4). Echo or debug hosts on a secret-bound allowlist reflect the value into `~/.microsandbox/sandboxes/<name>/logs/exec.log`; the policy editor warns when a known echo host (`httpbin.org`, `postman-echo.com`) is allowed alongside a binding.

**Transports outside the app's spawn path.** The SSH alias's `ProxyCommand` (`msb_proxy_command` in `src-tauri/src/backends/mod.rs`) is spawned by `ssh`/Mutagen, not the app, so it carries no start environment. On a stopped secret-bound or chained sandbox its implicit `msb exec` start fails closed. The app always starts a sandbox explicitly before opening sync or panes, so the failure appears only if Mutagen reconnects to a sandbox the user stopped.

**Parallel worktrees.** New paths: all under `app_data_root` (above). New host port: the SOCKS port is allocated at runtime from the OS ephemeral range, never a constant, so concurrent runs cannot collide by construction. Host-global resources: the msb sandbox store, the pulled mitmproxy image and `runtime.log` are per-user microsandbox state; this feature only reads `runtime.log`, the image pull is idempotent, and sidecar names derive from sandbox names, so it adds no new host-global name. Real-msb specs belong to the `standard` tier, which already runs one at a time host-wide. New teardown of host-global state: the startup sweep of microsandbox sidecars is scoped to this app's data root (Decision 20) and runs only without `MIO_MOCK_BACKEND`. No new bundled binary and no new harness environment variable.

**Mock-backend convention.** Every new external call crosses the `ProcessRunner` seam through `MsbProvider` (`msb.pull`, `msb.--version`, sidecar `msb.create`/`msb.stop`), so the light tier covers the flows with `ScriptedMsbRunner` and the new call journal, not a hand-written mock struct. Host-side work with no process (`wait_sidecar_ready`, `wait_for_ca`, the `runtime.log` read) is gated on `mock_backend_enabled()`.

**i18n.** Every new user-facing string lands as an English literal marked `// TODO(i18n)`. Paraglide keys in `messages/en.json`, `messages/de.json` and `messages/ru.json` are added only after the user has approved the working feature, per the `feature-implement` skill.

**Cross-feature effects (docs not edited here).** `docs/features/network-proxy/02_dev.md` Resolved Decision 9 (microsandbox refused) is superseded for microsandbox by Phases E–F. `docs/features/proxy-network-policy/02_dev.md` must adopt `.mio/net-policy.json` (Decision 6). `docs/features/proxy-toggle-management/02_dev.md` shares the `SandboxBackend::recreate` seam (Phase G). `docs/features/proxy-credential-secrets/02_dev.md`'s planned `SecretSource` changes how a `secrets.json` entry resolves; `AppStartEnv` must call the same resolver once that lands, so credential-sourced values also reach microsandbox.

## Common Gotchas

| Gotcha | Cause | Fix |
|---|---|---|
| `microsandbox does not support a network attachment or environment variables` from `create_sandbox` | `MsbProvider::create_instance` (`src-tauri/src/provider/msb.rs`) still refuses `InstanceSpec.network`/`env`, which only the Podman `ProxyAttachment::PodmanBridge` sets | Carry microsandbox policy in `InstanceSpec.egress` and the chain in `ProxyAttachment::MsbChain`; never map a microsandbox attachment onto `network`/`env` |
| `msb start`/`exec` fails `host environment variable X is not set` | A start-capable `msb` call was spawned without `StartEnvSource::env_for`, or the call bypassed `run_starting`/`exec_command_inner` in `src-tauri/src/provider/msb.rs` | Route every `create`, `start` and `exec` spawn through the start-environment path; check `<app_data_root>/net-policy/<sandbox>/applied.json` exists |
| Create fails `secret "<id>" has no stored value` | A binding in `.mio/net-policy.json` names a secret id absent from `<app_data_root>/proxy/secrets.json`; `AppStartEnv` refuses rather than letting `msb` read an inherited same-named variable | Store the value through `set_proxy_secret` in `ProxyPanel.svelte`, or remove the binding |
| A real secret value appears in argv, `mio.log` or a guest file | The value was rendered into `--env`/`--secret` text or written to `.mio/` | `msb_policy::render` emits variable names only; values travel only through `ProcessRunner::run_with_env` (`src-tauri/src/process/types.rs`) |
| `run_with_env` returns `Unsupported` | The default `ProcessRunner::run_with_env` refuses non-empty environment for runners that did not override it | Override `run_with_env` in the runner (`SystemMsbRunner` in `src-tauri/src/process/mod.rs`, `ScriptedMsbRunner` in `src-tauri/src/mockctl/mod.rs`) |
| Every HTTPS call fails `SSL_ERROR_SYSCALL` under allowlist | `--net-strict` defaults to true and the authority cannot be inspected without interception | `msb_policy::render` must emit `--tls-intercept` whenever the mode is allowlist, a rule, a secret or a proxy exists |
| Denied hostnames still resolve in DNS | An `allow@dns` rule opens the resolver to every name | Never emit `allow@dns` from `src-tauri/src/provider/msb_policy.rs`; domain-allow rules resolve exactly the allowed names |
| Editing `.mio/net-policy.json` changes nothing in the running sandbox | microsandbox fixes network rules at `msb create`; `msb modify` has no network-rule flag | Use the re-apply action (`reapply_sandbox_network`, Phase G), which recreates around the preserved volume; `net_policy_drift` flags the pending change |
| Re-apply fails `already attached with an incompatible disk mode` | `recreate_instance` created the new instance before `msb rm` finished; a `kind=disk` volume admits one attached sandbox | Await `msb rm --force` before `create_instance` in `MsbProvider::recreate_instance`, and never pass the volume to `volume rm` there |
| Sidecar `msb create` fails `unexpected argument` | `msb create` takes no command | `MsbProvider::create_sidecar` maps `SidecarSpec.command` to `--script start=<body>` plus `--init /.msb/scripts/start` |
| Sidecar addon never fires and `flows.ndjson` stays empty, no error | Addons were delivered with `--copy-dir`, which leaves files with a 1970 mtime | Deliver `addons/` with `--mount-dir <host>:/addons:ro` |
| `TrafficPanel.svelte` stays empty for a microsandbox sandbox although the sidecar runs | The addon wrote `/addons/flows.ndjson` because `MIO_FLOWS_PATH` was not set in the script body, or `flows_path` ignored `meta.json`'s provider | Set `MIO_FLOWS_PATH=/flows/flows.ndjson` in `script_body`'s command and resolve `flows_path` from `meta.json` (`src-tauri/src/proxy/mod.rs`) |
| Viewer or re-apply hangs while stopping the sidecar | `msb stop` without `-f` never finishes draining an `--init` sidecar | Use `MachineProvider::stop_sidecar`, which maps to `msb stop -f` on `MsbProvider` |
| Agent gets `curl (7)` right after the sidecar reports `running` | msb reports `running` about 3 s before mitmdump listens | Call `provider::probe::wait_sidecar_ready` after every sidecar create and start |
| Agent HTTPS fails `curl (52)`/`(56)` with nothing in `runtime.log` | Wrong SOCKS password, stopped sidecar or missing upstream CA all fail closed and silent | Read `ProxyStatus.healthy`; recreate the sidecar on the same `certs/` directory; check `meta.json`'s password matches the htpasswd |
| Agent chain breaks after the sidecar was recreated | The sidecar got a fresh confdir, so its CA no longer matches the agent's `--tls-upstream-ca-cert` | Keep `<app_data_root>/proxy/<sandbox>/certs/` across sidecar recreates; deleting it requires re-applying the agent |
| Sidecar create fails repeatedly with `PortInUse` | The ephemeral port picked by `proxy::allocate_socks_port` was taken before `msb create` bound it | `create_proxy` retries up to three times; a persistent failure on a later start needs the re-apply action, because the agent's `--proxy` URL is fixed |
| The SOCKS password shows in `msb inspect` | The script body carried `--proxyauth user:pass` | Use `--proxyauth @/addons/htpasswd` (Decision 7); the plaintext stays in `meta.json` under `app_data_root` |
| `secretInjected` is true for a request that carried no placeholder | Decision 10 marks every row to a secret-bound host; mitmproxy cannot observe microsandbox's substitution | Treat the column as "secret-bound host" for microsandbox; never derive it from header values |
| One worktree's app removes another run's microsandbox sidecar at startup | An unscoped `proxy::sweep` treated a sidecar whose agent did not exist yet as orphaned | Sweep a microsandbox sidecar only when its `meta.json` exists under this app's `app_data_root` (Decision 20) |
| Readiness reports not-ready on a working microsandbox host | `msb --version` is below `MIN_MSB_VERSION` (0.7.12) or its output did not parse in `parse_msb_version` (`src-tauri/src/machine/msb.rs`) | Run `msb self update` from a copy of `msb.exe`; fix the parser if the version string changed |
| Light spec hangs about 10 s in `create_proxy` | `wait_for_ca` polls for a CA no mitmdump writes on the light tier | Keep the `mock_backend_enabled()` stub CA write in `create_proxy` (`src-tauri/src/proxy/mod.rs`) |
| Mutagen reports a transport failure for a stopped secret-bound sandbox | The alias's `ProxyCommand` runs `msb exec` outside the app, without the start environment, and the implicit start fails closed | Start the sandbox from the app before syncing; the failure is fail-closed by design |
| Traffic viewer shows no DNS or UDP | DNS is answered by microsandbox's gateway and SOCKS5 mitmproxy has no UDP | Documented limitation in `TrafficPanel.svelte`; the viewer covers TCP/HTTPS only |
| Sidecar init script fails `Unterminated quoted string` | The body went through `--script`, which decodes `\'` and `\\` and so breaks `shell_quote`'s `'\''` | Pass the body to `--script-raw` with its own `#!/bin/sh` line, as `MsbProvider::create_sidecar` does |
| Sidecar is `running` but the SOCKS port answers another process, and `msb create` exited 0 | A taken published port is logged only in `<msb home>/sandboxes/<name>/logs/runtime.log` (`published TCP port listener failed`) | `port_bind_failed` in `src-tauri/src/provider/msb.rs` maps it to `PortInUse` after a sidecar create and after every start |
| Every light spec fails `session not created: This version of Microsoft Edge WebDriver only supports Microsoft Edge version N` | The staged `tools/msedgedriver.exe` is older than the installed WebView2 runtime | `./build.exe e2e` now re-stages the driver itself when the major versions differ (`check_e2e_driver` in `build.rs`); if it prints a re-stage warning, run `./build.exe e2e --setup` to install `msedgedriver-tool` |
