# Package Autocomplete — E2E Test Plan

This document is the test plan for the autocomplete feature described in `docs/features/package-autocomplete/02_dev.md`. That plan adds a `list_registry` Tauri command, a process-lifetime registry cache in `src-tauri/src/runtime/mod.rs`, and a `Command`-backed suggestion dropdown in `src/routes/projects/SandboxItem.svelte`. No spike has been run against the built application for this test plan; the de-risking section below lists the two risks to clear by hand before the spec is written.

## Goal

The test must prove four things through the running application:

1. **The `list_registry` command is wired and the registry loads.** Focusing the package input in a live sandbox row must cause `ensureRegistry` (`src/lib/registry.svelte.ts`) to call `invoke("list_registry", { name })`, which runs `mise registry --json` in the container via `PodmanMiseRuntime::registry` (`src-tauri/src/runtime/mod.rs`) and returns the entries. The test confirms this by asserting suggestion items appear after focus — a test that drives `podman exec mise registry --json` directly would bypass the `RuntimeManager` trait, the `OnceCell` cache, and the entire Tauri command wiring, and would therefore have no teeth.
2. **Suggestions include descriptions.** Each visible suggestion must show the tool's description below its short name, proving `mise registry --json` (not the plain text format) was used and that the description field reached the frontend.
3. **Selecting a suggestion populates the input.** Clicking a suggestion item must set `packageInput` to the tool's short name, proving the `Command.Item` `onSelect` handler fired and the blur-click race (the `setTimeout(0)` deferral in `SandboxItem.svelte`) is correctly handled.
4. **The install flow works end-to-end after autocomplete selection.** Installing via a suggestion-selected name must produce the same result as typing the name manually — the package chip appears and `mise.toml` records the tool — proving autocomplete is an input aid, not a parallel install path.

A weaker test that only asserts the `list_registry` IPC return value (e.g. via a Tauri unit test) would miss whether the frontend renders the dropdown, handles the blur race, and passes the selected name into the existing `installPackage()` thunk correctly.

## Existing Test Styles

The repository has two styles; the new test belongs to the first:

- **App-driven WebdriverIO specs** (`e2e/test/specs/*.spec.ts`) launch the compiled Tauri binary via `tauri-driver`, drive the real UI through page objects (`e2e/test/pageobjects/`), and read ground truth from `podman --connection` and the laptop filesystem. `e2e/test/specs/runtime-management.spec.ts` and `e2e/test/specs/project-start-stop.spec.ts` are the nearest templates: the former uses a `function ()` describe block with a raised `this.timeout` and a per-test `afterEach` diagnostics dump; the latter is local-only (no `REMOTE_CONNECTION`). The new spec is local-only like `project-start-stop.spec.ts`.
- **Standalone POCs** (`e2e/` root scripts) exercise a transport in isolation without launching the app. Not used for this feature.

## Chosen Approach

Add `e2e/test/specs/package-autocomplete.spec.ts`. The topology is local-only: one `LOCAL_CONNECTION` Podman machine (`mio-tests`), no remote host. The spec creates one project, exercises the autocomplete widget, and verifies the full install completes. Local-only is sufficient because the autocomplete is frontend-only; the `list_registry` command runs entirely on the local machine and the install path is already covered by `runtime-management.spec.ts` for the remote case.

The test tool is **`jq`**: the same tool `runtime-management.spec.ts` uses, proven installable from the mise registry in the spike. Using `jq` keeps the local install fast (static binary, no runtime dependencies) and avoids downloading a language runtime per test run. The search prefix used to trigger autocomplete is `"jq"`, which matches the `jq` entry and a small number of others (`jq-lsp`, `jqp`), giving a bounded list that is easy to assert against.

## Harness Changes

No changes to `e2e/wdio.conf.ts` are required. The `onPrepare` hook already:
- provisions `mio-tests` via `provisionMachine`,
- stages the mise base image on `LOCAL_CONNECTION` with `ensureMiseBaseImage`,
- builds the debug Tauri binary.

The spec's `after` hook removes the created container with `podman(LOCAL_CONNECTION, ["rm", "-f", projectName], { check: false })`, matching the cleanup pattern in `runtime-management.spec.ts`.

### Page object additions (`e2e/test/pageobjects/project-row.component.ts`)

Add the following members. No existing members are changed; the `packageInput` getter (`input[placeholder='package name']`) continues to resolve correctly because the `<input>` element is preserved inside the new relative wrapper.

```ts
// The suggestion dropdown rendered by Command.Root when the input has filtered results.
// Command.List in cmdk-sv renders with role="listbox".
get suggestionList(): Element {
    return this.root.$("[role='listbox']");
}

// All visible suggestion items. Command.Item in cmdk-sv renders with role="option".
get suggestionItems(): Promise<Element[]> {
    return this.root.$$("[role='option']");
}

// The short-name text of every visible suggestion.
async visibleSuggestions(): Promise<string[]> {
    const items = await this.suggestionItems;
    const names: string[] = [];
    for (const item of items) {
        const span = await item.$("span.font-mono");
        if (await span.isExisting()) names.push(await span.getText());
    }
    return names;
}

// The description text of the first suggestion matching `shortName`, or "" when absent.
async suggestionDescription(shortName: string): Promise<string> {
    const items = await this.suggestionItems;
    for (const item of items) {
        const nameSpan = await item.$("span.font-mono");
        if (!await nameSpan.isExisting()) continue;
        if ((await nameSpan.getText()) !== shortName) continue;
        const desc = await item.$("span.text-muted-foreground");
        return await desc.isExisting() ? desc.getText() : "";
    }
    return "";
}

// Focus the package input (triggering registry load) and type `text`.
async typeInPackageInput(text: string): Promise<void> {
    const input = await this.packageInput;
    await input.scrollIntoView();
    await input.click();       // focus triggers ensureRegistry
    await input.setValue(text);
}

// Click the suggestion item whose short name exactly matches `shortName`.
async selectSuggestion(shortName: string): Promise<void> {
    const items = await this.suggestionItems;
    for (const item of items) {
        const span = await item.$("span.font-mono");
        if (await span.isExisting() && (await span.getText()) === shortName) {
            await item.scrollIntoView();
            await item.click();
            return;
        }
    }
    throw new Error(`suggestion "${shortName}" not found in the dropdown`);
}

// The current value of the package input field.
async packageInputValue(): Promise<string> {
    return (await this.packageInput).getValue();
}
```

## Spec Scenario

### `e2e/test/specs/package-autocomplete.spec.ts`

```
describe("Package autocomplete", function () {
    this.timeout(300000);
    projectName = `e2e-autocomplete-${Date.now()}`;
    row = ProjectsPage.row(projectName);
```

1. **Create the project.** `await ProjectsPage.open(); await ProjectsPage.createProject(projectName);` Assert `row.root` is displayed.

2. **Focus the input and type a search prefix.** `await row.typeInPackageInput("jq")`. This focuses the input (triggering `ensureRegistry` → `invoke("list_registry", { name: projectName })` → `mise registry --json` in the container), types `"jq"`, and updates `packageInput` to `"jq"`.

3. **Assert suggestions appear.** Poll with `browser.waitUntil` (timeout 60 s, interval 1 s) until `(await row.visibleSuggestions()).length > 0`. The 60 s window covers the `list_registry` round trip — `mise registry --json` runs over `podman exec`, which starts the container if needed and returns 983 entries.

4. **Assert `jq` is among the suggestions.** `assert((await row.visibleSuggestions()).includes("jq"))`. This confirms the registry returned `jq` and the client-side substring filter matched it.

5. **Assert `jq`'s description is shown.** `const desc = await row.suggestionDescription("jq"); assert(desc.length > 0)`. This proves `mise registry --json` was used (the text-format output has no description column) and that the `description` field survived the Rust→frontend round trip.

6. **Select the `jq` suggestion.** `await row.selectSuggestion("jq")`. This clicks the `Command.Item` for `jq`; the `setTimeout(0)` deferral in the `onblur` handler allows the `onSelect` to fire first and set `packageInput = "jq"`.

7. **Assert the input is populated.** `assert.strictEqual(await row.packageInputValue(), "jq")`. This proves the `onSelect` handler wrote to `packageInput` and the blur race did not close the dropdown before the click registered.

8. **Install via the Install button.** `await row.installPackage("jq")` (the existing waiting helper — it calls `setValue("jq")` which is idempotent since the value is already `"jq"`, then clicks Install and waits for the chip). The chip appearing proves the full `install_package` → `mise use jq` → `list_packages` → UI re-render path completed successfully after autocomplete selection.

9. **Cleanup.** `after`: `podman(LOCAL_CONNECTION, ["rm", "-f", projectName], { check: false })`.

## De-Risking Spike Results

No spike has been run against the built application. Two risks must be cleared by hand before the spec is written.

**Risk 1 — blur-click race is actually handled (feature-fix concern).**
The `onblur` handler sets `showSuggestions = false` after a `setTimeout(0)` deferral (`SandboxItem.svelte`). If WebdriverIO's click on a `Command.Item` fires the blur on the input before the click event reaches the item, the dropdown closes before `onSelect` fires and `packageInput` is never populated. To clear: build the feature, run the app, focus the input, type `"jq"`, click the `jq` suggestion, and confirm `packageInput` shows `"jq"`. If clicking the suggestion dismisses the dropdown without populating the input, the `setTimeout` deferral is insufficient inside WebView2 and must be replaced with a `mousedown` / `pointerdown` guard (set `showSuggestions = false` only on `blur` when the newly focused element is not inside the dropdown container). This is a feature fix — resolve it before writing step 6 of the spec.

**Risk 2 — `[role="option"]` is the correct selector for `Command.Item` (test concern).**
The page object uses `[role="option"]` to locate suggestion items, based on the cmdk-sv library that shadcn-svelte's Command component wraps. If cmdk-sv renders items with a different role or a `data-cmdk-item` attribute instead, the `suggestionItems` getter returns an empty array and step 4 never asserts successfully. To clear: after Phase B lands, open the browser devtools inside the running app, focus the package input, type `"jq"`, and inspect the rendered dropdown DOM to confirm the role or attribute. Update `suggestionItems` in the page object to match the actual rendered attribute before writing the spec. This is a test concern only — the feature is correct regardless of which selector the test uses.

## Common Gotchas

| Gotcha | Cause | Fix |
|---|---|---|
| Step 3 times out — no suggestions appear after 60 s | `list_registry` failed silently (container did not start, or `mise registry --json` errored) and `registryEntries()` returned `[]` | Run `podman exec <name> mise registry --json` directly in the terminal to confirm it works; check that the sandbox container exists and the mise base image is staged on `LOCAL_CONNECTION` |
| `selectSuggestion("jq")` closes the dropdown without populating `packageInput` | The blur event on the input fires before the `Command.Item` click event, closing the dropdown before `onSelect` runs | Replace the `setTimeout(0)` deferral in the `SandboxItem.svelte` `onblur` handler with a `pointerdown` guard that sets a flag to suppress the next `blur` (see Risk 1 in De-Risking) |
| `suggestionItems` returns an empty array even though the dropdown is visible | cmdk-sv renders `Command.Item` with an attribute other than `role="option"` | Inspect the dropdown DOM in devtools and update the `[role='option']` selector in `project-row.component.ts` to match the actual rendered attribute (see Risk 2 in De-Risking) |
| `typeInPackageInput("jq")` does not trigger the registry fetch | `input.click()` did not fire the Svelte `onfocus` handler, so `ensureRegistry` was never called | Use `input.click()` before `input.setValue()` (already in the helper); if `onfocus` is still not firing, add a brief `browser.pause(100)` between click and setValue to let the event propagate |
| Step 7 asserts `packageInputValue() === "jq"` but finds `""` | The `Command.Item` `onSelect` set `packageInput = "jq"` but Svelte's binding did not update the DOM `value` attribute in time for `getValue()` | Wrap step 7's assertion in a `browser.waitUntil` polling `packageInputValue()` with a short timeout (2 s) before asserting |
| `installPackage("jq")` in step 8 re-types `"jq"`, overwriting what autocomplete set | `setValue` in the page object clears the input before typing; the result is correct but the test does not isolate the autocomplete-to-install path | Accept this: `setValue("jq")` on an input already containing `"jq"` is idempotent in effect; step 7 already proved autocomplete populated the field |
| The suggestion dropdown overlaps the Install button and `#clickButton` fails | The `z-50 absolute` dropdown sits over the Install button when `jq` is typed | Call `selectSuggestion` before clicking Install; once `showSuggestions = false` the dropdown is gone and the Install button is interactable |
| All 983 suggestions render at once, freezing the UI | `filteredEntries` in `SandboxItem.svelte` is not sliced to 20 | Confirm `filteredEntries` uses `.slice(0, 20)` as specified in `02_dev.md`; if the UI freezes, the slice is absent and `SandboxItem.svelte` must be fixed |
