# Proxy Credential Secrets: E2E Test Plan

This document is the test plan for `docs/features/proxy-credential-secrets/02_dev.md`: a Podman sandbox behind an iron-proxy sidecar holds only `GITHUB_PLACEHOLDER` (`ghp_MioPlaceholder0000000000000000000000`), and the sidecar swaps the placeholder for the real token in the `Authorization` header of requests to GitHub's hosts. The swap for `github.com`, `api.github.com` and `uploads.github.com` was proven by the 2026-11-18 spike (`docs/features/github-cli-auth/spike/proxy-swap.md`). No spike has been run for this plan. Status: both specs exist. The light spec passes (`pnpm run test:light` with `MIO_SPEC=github-access-mode`). The standard spec typechecks and skips without `MIO_E2E_GITHUB_TOKEN`; the full standard run is pending a token. On 2026-11-18 the user manually verified every standard-spec scenario and all passed: placeholder-only guest, gh/git/curl swap, `X-Other` not swapped, `gist.github.com` and `raw.githubusercontent.com` swaps with the audit annotation, mise through the placeholder, rotation, stopped-sandbox offline refresh, delete while running, opt-out, microsandbox plaintext mode and migration. The automated standard run is still pending `MIO_E2E_GITHUB_TOKEN`.

## Goal

Prove through the real application, with a real Podman machine and the pinned iron-proxy sidecar, that:

- **Placeholder only in the sandbox:** after `set_github_token` (`src-tauri/src/commands/credentials.rs`), the sandbox's `/root/.config/gh/hosts.yml`, `gh auth token` and the mise env (`GITHUB_TOKEN`, `MISE_GITHUB_TOKEN`) hold the placeholder and never the token, while `gh api user` succeeds through the sidecar.
- **Swap scope:** the swap happens for `Authorization` on the five bound hosts only. The spike left `gist.github.com`, `raw.githubusercontent.com` and mise through the placeholder unproven; this plan proves them.
- **Opt-out and mode split:** an opted-out sidecar sandbox gets no token and an empty mise env; a plaintext-mode sandbox (no sidecar, microsandbox) keeps the real token.
- **Refresh and migration:** save, rotation and delete refresh every sidecar-mode sandbox, running or stopped (a stopped sidecar's files are rewritten offline); a sandbox holding the plaintext token is re-applied with the placeholder.
- **Manage card:** `data-github-mode` and the text "token kept securely" / "token stored in sandbox" match the sandbox's mode.

A weaker test would miss the following. A unit test of `render()` cannot show that the sidecar reloads before gh's online validation. A mock-backend test has no sidecar, so it cannot show the swap, the offline refresh of a stopped sidecar, or that the token is absent from the guest.

## Chosen approach

Two specs: `standard` as the source of truth, `light` for the plaintext-mode and opt-out card edge cases that need no podman.

| Spec | Tier | Covers |
|---|---|---|
| `e2e/test/specs/standard/github-placeholder-swap.spec.ts` | standard | Scenarios 1-8 against a real sidecar |
| `e2e/test/specs/light/github-access-mode-ui.spec.ts` | light | Card mode and opt-out in plaintext mode on the mock backend (Scenario 9) |

**Why standard.** The swap is only real behind a live iron-proxy sidecar on an internal Podman network. Copy the shape of `e2e/test/specs/standard/podman-egress-boundary.spec.ts` (`guestSh`, `guestCurl`, `LOCAL_CONNECTION`, create through the UI, workspace policy seeded before create). The feature is not `heavy`: no large download and no remote deploy. A `standard` run takes the host lock and serialises against every other real-infra run on the machine; that is the intended cost of real coverage.

**Why the sidecar card state is not in light.** `github_sandbox_status` is a real host-side command, and `sidecar_mode` derives from the sidecar's `meta.json` under the run's app-data root, which the mock backend never writes. Light therefore always sees `data-github-mode="plaintext"`. Adding mock support (seeding `meta.json` to fake sidecar mode) is rejected: it would fake the one fact under test and couple the spec to a private file layout. The sidecar-mode card assertions go to the standard spec; light covers the plaintext half only.

**Real token.** The standard spec reads a read-only token (fine-grained or classic, no write scopes) from the environment variable `MIO_E2E_GITHUB_TOKEN`. Rules:

- When the variable is unset, the spec skips itself with a clear message; it never fails a machine without the token and never defaults the value.
- The spec hands the token to the app only through `invokeCmd("set_github_token", ...)` (write-only over IPC) and compares against it in memory. It never logs the token, interpolates it into an assertion message, writes it to a file, or types it into a visible input, because `captureDiagOnFailure()` dumps page source.
- Guest-side leak scans output a match count only, never matching lines.
- No write reaches GitHub: only `gh api user`, `git ls-remote` and `curl` GETs. The spike's `git push --dry-run` is left out.
- `after()` calls `delete_credential_bundle`. The credential store lives under the run's isolated app-data root, so the developer's real credential store is untouched.

**Parallel-worktree constraints.** Every host path derives from `APP_DATA_ROOT` and `WORKSPACE_ROOT` in `e2e/lib/run-identity.ts`; the sidecar token file is read at `<APP_DATA_ROOT>/proxy/<sandbox>/secrets/mio-github` (02_dev.md, Resolved Decision 14: the feature adds no host-global state). The spec asserts file content or deletion of its own sandbox's files, never that an unrelated path does not exist. Sandbox names are unique per run (`e2e-gps-<timestamp>`). The light spec runs concurrently with other worktrees' light runs without issue.

**Prerequisites.** `mio-tests` machine provisioned by the standard `onPrepare`; network access to GitHub; a workspace policy that allows the five GitHub hosts (the starter policy `STARTER_BASE_HOSTS` already does). No `wdio.conf.ts` change.

## Spec scenario

Standard spec (calls `captureDiagOnFailure()`; budgets from `e2e/lib/timeouts.ts`):

1. **Create sandbox A (sidecar mode)** through the UI. Deviation: A uses open egress with no seeded policy, which already reaches GitHub. Assert `<APP_DATA_ROOT>/proxy/A/meta.json` names the iron-proxy engine and `podman ps` lists the `A-proxy` sidecar.
2. **Save the token** with `set_github_token`. Wait for `[data-github-access]` to reach `data-state="applied"`. Assert `data-github-mode="sidecar"` and that the card text contains "token kept securely" and not "token stored in sandbox".
3. **Placeholder in the guest.** `podman exec` reads `hosts.yml`: it contains the placeholder, and a count-only scan finds 0 occurrences of the token across `/root` and the process env. `gh auth token` prints the placeholder.
4. **Swap works.** In the guest, `gh api user` exits 0 and `git ls-remote` of a public repository succeeds. The host file `mio-github` equals the trimmed token, with no trailing newline (compared in memory).
5. **Unproven hosts.** In the guest, send GETs with `Authorization: Bearer <placeholder>` to `raw.githubusercontent.com` (a public file; an unswapped placeholder gets 404 where the swap gets 200) and to `gist.github.com`. Assert each audit row carries the secret-injected marker (read it as `podman-egress-boundary.spec.ts` reads audit rows). A request with the placeholder in `X-Other` is not swapped.
6. **mise through the placeholder.** Deviation: the app exports `GITHUB_TOKEN` and `MISE_GITHUB_TOKEN` only to its own mise execs, so `podman exec` cannot observe them; the spec sets both to the placeholder explicitly. In the guest, `GITHUB_TOKEN` and `MISE_GITHUB_TOKEN` equal the placeholder. Run a `mise ls-remote` for an aqua-backed tool (it reads `raw.githubusercontent.com`) and assert exit 0 and no `401`/`404` in stderr.
7. **Rotation and stopped refresh.**
   - Save the token again (a new stamp, the same or an alternate `MIO_E2E_GITHUB_TOKEN_ALT` value). The card re-applies and `gh api user` still works with the guest value unchanged.
   - Stop A, then call `delete_credential_bundle`. Assert `mio-github` is deleted while the sidecar is stopped. Save the token again and assert the file holds it again. Start A and assert `gh api user` works with no further action.
   - Delete the credential with A running. Deviation: `github::remove` deletes `hosts.yml`, so the spec asserts `gh api user` fails, `hosts.yml` holds no token, and a placeholder curl to `api.github.com` returns 401. The token reaches the guest only through stdin, never argv.
8. **Opt-out, plaintext and migration.**
   - Re-save the token, then switch A's card off (`set_github_sandbox_access`). Assert `data-state="opted-out"`, `mio-github` deleted, an empty mise env on the next exec, and `gh api user` failing.
   - Create sandbox B as a microsandbox sandbox (topology from `microsandbox-egress-allowlist.spec.ts`). Assert `data-github-mode="plaintext"`, "token stored in sandbox", and that `hosts.yml` holds the token (compared in memory).
   - Migration: with A back on, write the token into A's `hosts.yml` through `podman exec` and set the state file's applied outcome to `swapped: false`, then call `set_github_sandbox_access(enabled: true)`. Assert `hosts.yml` holds the placeholder and the token count is 0.

Light spec:

9. **Plaintext card and opt-out on the mock backend.** Deviation: the sandbox must be started before the card leaves `pending`, and opt-out uses the card switch `[data-github-access-switch]`. Create a mock sandbox and `set_github_token` with a sentinel value (never a real token). Assert the card shows `data-github-mode="plaintext"` and "token stored in sandbox"; switch opt-out on and assert `data-state="opted-out"`; delete the credential and assert `data-state="no-credential"`.

## De-risking spike results

No new spike. Cleared by the 2026-11-18 spike: Basic and Bearer swaps, `gh auth login` with the placeholder, `git ls-remote`, binding removal and restore. Still unproven and covered by Scenarios 5 and 6: `gist.github.com`, `raw.githubusercontent.com`, and mise through the placeholder (Resolved Decision 15 verified mise's header behaviour from source and one anonymous `curl` only). No known blocker; the spec does not need to wait.

## Open items

- Resolved: the repository defaults to `github/gitignore` (file `README.md`), overridable by `MIO_E2E_GITHUB_REPO`; the aqua tool is `aqua:BurntSushi/ripgrep`.
- Resolved: the audit source is `podman logs <sandbox>-proxy`, parsed for rows whose `request_transforms[secrets].annotations.swapped` is non-empty. The Traffic panel's `flows.ndjson` is not used because it only fills while the panel is open. Rows are matched by host and position after a pre-request snapshot.
- Remaining coverage gap: the app's own env injection of `GITHUB_TOKEN` and `MISE_GITHUB_TOKEN` into its mise execs, and the empty mise env on opt-out, are not asserted, because `podman exec` cannot observe them.
- A mock-backed sidecar-mode light spec stays out; revisit only if the mock gains a sidecar.

## Common Gotchas

| Gotcha | Cause | Fix |
|---|---|---|
| The spec fails on a machine without a token | `MIO_E2E_GITHUB_TOKEN` is unset | Skip the standard spec when the variable is unset; never default it |
| A failure message or diag dump contains the token | An assertion message interpolated the compared value, or the token was typed into a visible input | Fixed assertion strings, count-only leak scans, and saving through `set_github_token` |
| The light spec shows `data-github-mode="plaintext"` for a "sidecar" sandbox | The mock backend writes no sidecar `meta.json`, so `proxy::sidecar_engine()` reports no iron-proxy | Assert sidecar-mode card state only in the standard spec |
| `gh api user` returns 401 right after the token save | The guest call ran before the sidecar reloaded and gh applied | Wait for `data-state="applied"` before any guest call; the refresh precedes the apply (`02_dev.md`, Refresh paths) |
| The token comparison never matches `mio-github` | A trailing newline was added when the spec read or wrote the file | Compare the file's exact bytes to the trimmed token |
| The raw-host check passes without a swap | A public file is readable anonymously, so a 200 alone proves nothing about a bound host | Pair the 200 with the audit row's secret-injected marker |
| The microsandbox card shows sidecar mode | Sidecar mode is derived from `meta.json` on every call | Assert sandbox B has no iron-proxy `meta.json` before the card check |
| The light spec's card stays on `pending` | The sandbox was only created, not started | Start the sandbox before waiting for the card state |
| The standard or light run fails in a fresh worktree on missing staged binaries (mutagen) | `src-tauri/binaries/` is not staged in the new worktree | Run the main checkout's `build.exe dev --setup-worktree <worktree>` |
