# Workspace App Tabs — E2E Test Plan

This document is the test plan for `docs/features/workspace-app-tabs/02_dev.md`, whose Phases A–E
are all marked Implemented. No de-risking spike was run for this document itself — the one spike
this feature needed (whether a closed-and-reopened Terminal tab keeps its Zellij session) was
already run and recorded in `01_ideas.md`'s Validation section (2026-07-04, cleared with a required
design change, adopted as `02_dev.md` Resolved Decision 4). This document instead records that
implementing `02_dev.md` broke two pre-existing `standard` specs, and that fixing them was folded
into this pass rather than deferred, because they are the regression coverage this feature's own
behavioural changes invalidated.

## Goal

Prove, against the real backend (real `podman exec`, real `zellij web`, real Mutagen forwards — no
mock), that:

1. `open_workspace` embeds and activates only the sandbox's Dashboard/Manage pane — no Zellij
   daemon starts and no `.mio/zellij.json` token file appears until a Terminal pane is explicitly
   requested (`src-tauri/src/lib.rs`'s `open_workspace`, `embed_dashboard_on_main` activating on
   creation).
2. `open_terminal_pane` and `open_agent_web` are the lazy embed-or-switch paths for Terminal and
   Agents respectively, each reachable from the Manage tab's launcher
   (`src/routes/workspace/dashboard/+page.svelte`, `button[data-app]`), and structurally identical
   in shape (mirrors `open_agent_web`, per `02_dev.md`'s Resolved Decision).
3. `close_pane(name, kind)` closes exactly one non-Dashboard tab — tears down its Mutagen forward,
   re-activates the sandbox's Dashboard pane, and leaves the global panel narrow (not full-bleed) —
   and is a no-op when `kind` is `"dashboard"`.
4. A closed-and-reopened Terminal pane reuses the same session-name URL path
   (`http://127.0.0.1:<port>/<sandbox-name>`), the concrete fix `01_ideas.md`'s spike required so
   the underlying Zellij session (not exercised again here — already proven by the spike) is
   actually the one reattached to.
5. The switcher's two-level DOM contract (`div[data-sandbox]` → `button[data-app]` tabs +
   `button[data-close-tab]`/`button[data-close-sandbox]`) is real, clickable chrome, not just a
   `workspace_state()` read-back — `SWITCHER_H` grew from 40 to 64 logical px
   (`src-tauri/src/workspace/mod.rs`) and the geometry invariants (`workspace_layout`'s non-overlap,
   full-bleed-when-empty) still hold at the new height.

A `light`/mock-backend-only test would fail to cover all of this: it cannot prove the real Zellij
daemon never starts before a Terminal pane is requested (mock `RuntimeManager::prepare_terminal`
is a no-op regardless of when it's called), cannot prove a real Mutagen forward for one pane tears
down while a sibling's survives, and cannot prove the session-name URL actually reattaches to a
live `zellij web` session — all three are the actual claims Phases A–C make.

## Existing test styles

- **App-driven WebdriverIO specs**, `e2e/test/specs/{standard,light,heavy}/*.spec.ts` — drive the
  real Tauri app through page objects (`e2e/test/pageobjects/*.page.ts`,
  `e2e/test/pageobjects/*.component.ts`) and read backend state back through Tauri commands
  (`e2e/lib/workspace.ts`'s `workspaceState()` etc.), the CLI (`e2e/lib/podman-connection.ts`,
  `e2e/lib/mutagen.ts`), and the filesystem (`.mio/zellij.json`, `.mio/paseo.json`). This feature's
  coverage belongs here, in `standard` (see Tier selection below).
- **Dashboard-webview helper**, `e2e/lib/dashboard-suite.ts` — `useDashboardWebview()` +
  `dashboardIt()`, mandatory (per `e2e/AGENTS.md`) for any `standard` spec whose tests interact with
  a sandbox's dashboard pane (a separate WebDriver window handle from the main app webview). The new
  Manage-tab launcher is dashboard content, so tests clicking it must use this helper.
- **Multi-webview read-back, no page object for switcher content** — before this feature, no spec
  clicked switcher chrome directly by DOM (only `agent-web.spec.ts` did, via
  `workspace-switcher.page.ts`'s now-removed `agentsTab`/`paneTab` text selectors, which matched the
  flat `"{sandbox} — {title}"` button label the old switcher rendered). This feature's two-level
  switcher needed that page object's selectors rewritten to the new `data-*` contract (below) — the
  old text selectors have no equivalent string in the new markup.

## Chosen approach

**`standard`** (real `mio-tests` Podman machine, no downloads/model loads/remote deploys — `heavy`
is not warranted). No `light` companion is added: every claim above is specifically about real
process/forward lifecycle timing, which a mock backend cannot falsify, so a `light` spec here would
only assert UI/store logic already covered incidentally by the existing
`sandbox-create-row-ui.spec.ts`-style specs.

Two existing `standard` specs are fixed in place rather than superseded, because their assertions
describe the *old* eager-Terminal-embed model this feature replaces — running them unmodified
against the new backend fails, not because of a bug, but because the contract they assert is
exactly what changed:

- **`e2e/test/specs/standard/embedded-workspace.spec.ts`** — asserted `open_workspace` embeds
  Terminal *and* Dashboard (two panes, Terminal active) immediately. Rewritten to assert Dashboard
  alone embeds and activates, add a `open_terminal_pane` step that lazily embeds Terminal, add a
  `close_pane` step (close-one-tab, Dashboard re-activates, second call with `"dashboard"` is a
  no-op), and assert the Terminal pane's URL carries the stable `/<sandbox-name>` session path both
  on first open and after a close+reopen. `SWITCHER_H` in the test's local constant changed from 40
  to 64.
- **`e2e/test/specs/standard/agent-web.spec.ts`** — asserted `open_workspace` leaves a Terminal +
  Dashboard pair with no AgentWeb pane, and drove the switcher's now-removed inline "Agents" button
  via `workspace-switcher.page.ts`'s `clickAgentsTab`. Rewritten to expect only a Dashboard pane
  after `open_workspace`, and to open Agents via the Manage tab's launcher
  (`workspace-dashboard.page.ts`'s new `launchApp("agentweb")`) instead of switcher chrome. Also
  migrated to the mandatory `useDashboardWebview()` helper (it was hand-rolling the same
  switch-back + diag-capture `afterEach` pair the helper centralises), and its
  re-open-is-switch-not-duplicate test now switches onto Dashboard instead of a Terminal pane that
  this spec never opens.

## Harness changes

- **`src/routes/workspace/switcher/+page.svelte`** — added `data-sandbox={sandbox}` on each
  per-sandbox group, `data-app="dashboard"`/`data-app={app.kind}` on the tab buttons, and
  `data-close-sandbox`/`data-close-tab={app.kind}` on the close buttons. These did not exist when
  Phase D was implemented (this document did not exist yet); they are the minimal selector contract
  a two-level switcher needs, since the old flat switcher's `"{sandbox} — {title}"` button-text
  selector has no equivalent — the new tabs are icon-only, and their titles are translated
  (Paraglide), so a text selector would also break per-locale.
- **`src/routes/workspace/dashboard/+page.svelte`** — added `data-app={app.kind}` on each launcher
  button, for the same reason (translated title text is not a stable selector).
- **`e2e/lib/workspace.ts`** — added `openTerminalPane(name, workspacePath)` and
  `closePane(name, kind)` wrappers around the two new Tauri commands, mirroring the existing
  `openAgentWeb`/`closeWorkspace` wrappers.
- **`e2e/test/pageobjects/workspace-switcher.page.ts`** — replaced `agentsTab`/`paneTab`/
  `clickAgentsTab` (text-selector based) with `sandboxGroup`, `tab`, `closeTabButton`,
  `closeSandboxButton`, `clickTab`, `clickCloseTab` (all `data-*`-selector based, scoped under each
  sandbox's `data-sandbox` group).
- **`e2e/test/pageobjects/workspace-dashboard.page.ts`** — added `launcherButton(kind)` and
  `launchApp(kind)` for driving the Manage tab's Terminal/Agents launcher buttons.
- No `wdio.conf.ts` changes: no new provisioning, no new build step — the feature adds no new
  bundled component (Terminal/Agents already had prepare/embed code paths; only their call sites
  moved).

## Spec scenario

`embedded-workspace.spec.ts` (rewritten), in order:

1. Create and start sandbox A. *(unchanged)*
2. Click "workspace" (`open_workspace`) → poll `workspace_state()` until sandbox A has exactly one
   pane; assert its `kind` is `"dashboard"`, `forward_name` is empty, `url` includes
   `/workspace/dashboard`, and `active_app` is that pane's label. Assert `.mio/zellij.json` does
   **not** yet exist (no eager Zellij start). Assert the geometry invariants at `SWITCHER_H = 64`.
3. Call `open_terminal_pane(nameA, workspaceDirA)` → poll for the token file
   (`.mio/zellij.json`) → assert sandbox A now has two panes, the Terminal pane's `url` is a
   `127.0.0.1` loopback whose `pathname` is exactly `/<nameA>`, and it is the active pane.
4. `switch_pane` to Dashboard, assert the projects-list row narrows (unchanged assertions from the
   original spec), `switch_pane` back to Terminal.
5. Assert the real Zellij daemon (`zellij web --status` over `podman exec`) reports online, the
   `terminal-<name>` Mutagen forward is Connected, and the pane's URL serves HTTP 200.
6. Collapse/expand the global panel, assert rail/expanded geometry. *(unchanged)*
7. Call `close_pane(nameA, "terminal")` → poll until the `terminal-<name>` forward is no longer
   Connected → assert exactly the Dashboard pane remains, it is active, and the global panel is
   still `GLOBAL_EXPANDED_W` (not full-bleed). Call `close_pane(nameA, "dashboard")` and assert it
   is a no-op (pane count unchanged). Call `open_terminal_pane` again and assert the reopened pane's
   URL `pathname` matches the pre-close one exactly.
8. Re-click "workspace" on an already-open sandbox: assert idempotency (still exactly two panes,
   exactly one Connected forward). *(adjusted pane count from the original 2→2 assumption, since
   step 2 now starts at one)*
9. Create/start sandbox B, open its workspace: assert it gets a Dashboard pane, becomes active, and
   sandbox A's Terminal forward stays Connected throughout.
10. `switch_app(nameA)` brings sandbox A's last-active pane (Terminal) back to the front.
11. Destroy sandbox A: assert all its panes and its forward are gone, `sandbox_last_pane` has no
    entry for it, and sandbox B's Dashboard pane is untouched.
12. Destroy sandbox B (the last one): assert the global panel returns to full-bleed
    (`switcher`/`content` rects collapse to zero-width).

`agent-web.spec.ts` (rewritten steps 3–4 only; steps 1–2 and 5–8 unchanged in intent):

3. Open the workspace: assert exactly one pane (`"dashboard"`), carrying the correct
   `workspace_path`. *(previously asserted a Terminal+Dashboard pair)*
4. `workspaceDashboard.switchToDashboard(projectName)` then `.launchApp("agentweb")` (the Manage
   tab's Agents button, `button[data-app="agentweb"]`) → poll for the AgentWeb pane → assert its
   label/forward name, that it is active, the persisted password file, the mise manifest lists
   paseo, the real `paseo` process is running in the container, and its forward is Connected.
   *(previously drove the switcher's since-removed inline "Agents" button)*

## De-risking spike results

Already recorded in `01_ideas.md` (2026-07-04, cleared with a required design change — see that
document's Validation section and `02_dev.md` Resolved Decision 4). No new spike was run for this
document: the two spec rewrites above are a direct, mechanical consequence of `02_dev.md`'s already-
settled design, not an open risk.

## Sequencing

1. Phases A–E of `02_dev.md` (already Implemented) had to land first — the rewritten specs assert
   the post-Phase-A/B/C/D behaviour and would not compile/pass against the pre-feature code.
2. The `data-*` selector hooks (Harness changes) had to be added to
   `switcher/+page.svelte`/`dashboard/+page.svelte` before the page-object rewrites, since the page
   objects select against them.
3. `embedded-workspace.spec.ts` and `agent-web.spec.ts` were fixed together with this document
   rather than left broken for a future session: both are `standard`-tier regression coverage that
   this feature's own behavioural changes invalidated, and leaving them red would mask a real
   regression under "expected failure, ignore it."
4. Running the rewritten specs against the real `mio-tests` machine is the one step not yet done as
   of writing — `cargo check`/`cargo test`, `pnpm check`, and `npx tsc --noEmit` (e2e project) all
   pass, but the `standard` tier itself (`pnpm test` in `e2e/`) takes several minutes per spec
   against real Podman and was not run in this pass. Run it before trusting this document's
   scenario fully proves the feature.

## Environment notes

- Requires the `mio-tests` Podman machine (`podman machine list` shows it `wsl`, currently running
  in this environment) — the same machine `e2e/wdio.conf.ts` provisions for the `standard` suite.
- No remote host, no `mio-tests-remote` machine, and no model download are needed — this feature
  touches only local embedded-pane lifecycle.
- A stray `sandbox-mio.exe` process from a previous interrupted run can hold a file lock on
  `src-tauri/target/debug/sandbox-mio.exe` and fail the `standard`-tier build step with `LNK1104`;
  kill it (`tasklist`/`taskkill` by PID) before re-running.

## Common Gotchas

| Gotcha | Cause | Fix |
|---|---|---|
| `embedded-workspace.spec.ts` fails asserting `panesFor(state, name).length === 2` right after `openWorkspace()` | The spec still assumes the pre-feature eager Terminal+Dashboard embed; `open_workspace` now embeds only Dashboard | Call `openTerminalPane(name, workspacePath)` (`e2e/lib/workspace.ts`) before asserting a Terminal pane exists |
| `agent-web.spec.ts`'s Agents-tab test times out finding `button*=${sandbox} — Agents` | The switcher's inline "open Agents" button was removed (subsumed into the Manage tab's launcher, `02_dev.md` Phase D); `workspace-switcher.page.ts`'s old `agentsTab`/`clickAgentsTab` selectors match nothing | Use `workspaceDashboard.switchToDashboard(sandbox)` + `workspaceDashboard.launchApp("agentweb")` instead |
| A `standard` spec's `button[data-app="…"]`/`data-close-tab`/`data-close-sandbox` selector finds nothing | `src/routes/workspace/switcher/+page.svelte` or `dashboard/+page.svelte` lost the `data-*` attribute in a later edit | Re-add `data-sandbox`, `data-app`, `data-close-tab`, `data-close-sandbox` per this document's Harness changes section — these are the only stable, locale-independent selectors for the two-level switcher and the launcher |
| `cargo build`/`tauri build --debug` fails with `LINK : fatal error LNK1104: cannot open file '...\sandbox-mio.exe'` | A previous test run's `sandbox-mio.exe` process is still alive, locking the binary | `tasklist //FI "IMAGENAME eq sandbox-mio.exe"`, then `taskkill //PID <pid> //F`, then re-run |
| A geometry assertion expects `SWITCHER_H` = 40 | Test still uses the pre-Phase-D switcher height constant | Update the spec's local `SWITCHER_H` constant to 64, matching `src-tauri/src/workspace/mod.rs` |
